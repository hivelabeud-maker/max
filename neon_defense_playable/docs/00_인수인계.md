## Context — 왜 만드는가

넷마블(프로젝트 옥토퍼스)이 **같은 캐릭터(리타)로 다른 무드의 페이크 플레이어블**을 추가 요청했다.

기존 1차 납품본 `pixel_survivor_playable` 은 **보라 던전 + 픽셀아트 + 조용한 UI**다.
2차 요청은 **어두운 우주 + 네온 탄막 + 조밀한 게임 UI** — 톤이 정반대다.

브리프 원문 요약:
- 가운데 캐릭터를 중심으로 몰려오는 적을 막아내는 **디펜스형** (← 1차와 코어 루프 동일)
- **"화려한 탄막 / 적에게 탄막이 닿으면 흩뿌려지는 이펙트 등 시각적 자극으로의 후킹이 최우선"**
- 9:16 / **25초 이내** / 추후 엔드카드 붙여도 30초 넘지 않도록
- 1차는 **캐릭터만 적용한 기본형**, 이후 몬스터·배경·스킬선택 변주 예정

**사용자 확정 사항 (2026-09-09):**
| 항목 | 결정 |
|---|---|
| 프로젝트 구성 | **별도 프로젝트로 복제** (기존 스킨 추가 아님) |
| 그래픽 무드 | **레퍼런스 무드(어두운 우주 + 네온)로 진행.** 넷마블 던전 아트 안 씀 |
| 재사용 범위 | **캐릭터(리타)만** 재사용 |

| HUD | **레퍼런스처럼 조밀하게** |

⚠️ **제약 2가지**
1. **전폭 딤 금지** — `qa.js` ⑥(L189-209)이 `fillRect(x≈0, y, W, h≥6)` 를 감지해 **빌드를 실패시킨다.**

2. **세로 예산** — `qa.js` ①이 `pf.h ≥ 480`, `play ≥ 430` 을 강제한다.
   스킬 피해 패널은 레퍼런스처럼 **측면**에 두어 세로를 아낄 것

⚠️ **우상단 톱니**: `docs/00_인수인계.md` §6-3 이 *"눌러도 반응 없는 버튼 = 광고 이탈 요인"* 을

## 요청을 어떻게 해석할 것인가 (1차에서 얻은 것)

작업자가 주는 피드백은 짧다. 아래는 1차에서 **실제로 어긋났던 사례**와 그 교훈이다.

### ⚠️ "이펙트가 너무 커" 류 — 범위를 먼저 되물을 것
1차에서 이 한 마디에 **발사 이펙트와 볼리 폭발을 전부 줄였다가** 두 번 정정받았다
("발사될때 이펙트 말한거야" / "팡 터져서 흔들리는건 다 좋아").

**매 발마다 반복되는 이펙트**(머즐 플래시·탄 트레일)와 **가끔 한 번 터지는 이펙트**
(볼리 충격파·콤보 텍스트·화면 흔들림)는 눈에 쌓이는 방식이 완전히 다르다.
반복형은 조금만 커도 화면을 덮고, 순간형은 커야 손맛이 난다.
→ **어느 쪽인지 불명확하면 줄이기 전에 물어볼 것.** 뭉뚱그려 줄이면 반대로 간다.

### 눈대중 2회 실패 = 실측으로 전환
CTA 텍스트 세로 중앙정렬을 두 번 눈대중으로 틀린 뒤, 버튼 PNG의 밝은 면 밴드를
픽셀로 재서 `0.411h` 를 얻고 해결했다(기하 중심 `0.5h` 가 아니었다 — 하단 30%가 베벨).
**같은 지적을 두 번 받으면 추정을 멈추고 실측한다.**

### 증상 보고는 그대로 믿되, 원인은 다시 찾을 것
"숫자가 느린 박자로 덜컥덜컥 올라간다" → 실제로 측정하니 **63% 프레임에서 값이 멈춰 있다가
한 번에 9씩 튀고 있었다.** 사용자의 표현은 정확했고, 원인은 스무딩 부재 + 반픽셀 렌더 2개였다.
→ 증상 설명은 신뢰하되 **원인은 계측으로 확인**한다. `tools/` 에 헤드리스 하네스가 있으니
   눈으로 판단하지 말고 수치를 뽑을 것.

### "왜 이렇게 했어?" 에는 의도를 설명할 것
1차에서 "9:16으로 안 보인다"는 지적이 있었으나 **광고 납품본은 기기 화면비에 맞춰
늘어나는 게 규격상 의도된 동작**이었다. 되돌리지 말고 먼저 설명하고,
시연용이 필요하면 별도 빌드(`playable_uihd_demo.html`)를 준다.
