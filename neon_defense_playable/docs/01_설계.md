# PIXEL SURVIVOR — 페이크 플레이어블 설계서

도트 캐주얼 액션 로그라이크 RPG의 캐릭터를 활용한 **탑다운 서바이버형 페이크 플레이어블**.
실제 게임을 재현하지 않는다. 광고적으로 더 단순하고 더 극적인 27초를 만든다.

---

## 1. 전체 아키텍처

### 1-1. 3층 분리

```
┌──────────────────────────────────────────────────────────────┐
│  DATA  — 교체 지점. 아트/수치/문구/연출 타임라인만 들어감        │
│  character.js · enemies.js · skills.js · timeline.js · theme.js│
├──────────────────────────────────────────────────────────────┤
│  GAME  — 규칙. 데이터를 읽어서 동작. 특정 IP를 모름              │
│  player · enemy · bullet · skill · director · hud             │
├──────────────────────────────────────────────────────────────┤
│  CORE  — 엔진. 게임 규칙조차 모름. 다음 프로젝트에 통째로 재사용   │
│  engine · stage · input · pool · grid · sprite · fx · fsm · cta│
└──────────────────────────────────────────────────────────────┘
```

**CORE는 다음 플레이어블에 그대로 복사된다.** 이번 프로젝트의 진짜 산출물은 이 레이어다.
선행 3개는 전부 단일 파일 1,400줄이라 재사용 지점이 없었다 — 그래서 매번 처음부터 만들었다.

### 1-2. 연출 감독(Director) 구조 — 이번 설계의 핵심

선행 사례가 공통으로 겪은 문제: **페이싱이 시뮬레이션 결과에 좌우된다.**
TOY WAR는 `buildTrack()`으로 거리축에 배치해 28.9초를 맞췄고, Penguin은 제한시간에 맡겼다가 95초가 됐다.

이번엔 **시간축 타임라인**이 게임을 지배한다.

```
director.tick(t)  →  t초에 정의된 큐(cue)를 실행
                     · spawn(적 종류, 수, 방향, 간격)
                     · state(전환)
                     · camera(줌/셰이크)
                     · banner / hint / slowmo
```

게임은 "적이 다 죽으면 다음"이 아니라 **"18.5초가 되면 보스"** 로 흐른다.
플레이가 아무리 이상하게 흘러도 27초에 끝난다. 광고에서는 이게 정답이다.

### 1-3. 프레임 예산

| 항목 | 상한 | 처리 |
|---|---|---|
| 동시 적 | 220 | 오브젝트 풀, 화면 밖 컬링 |
| 동시 탄/파티클 | 400 | 풀 재사용, GC 0 |
| 충돌 | 공간 해시 64px 셀 | O(n) 유지 |
| 데미지 숫자 | 40 (초과 시 오래된 것부터 회수) | |
| 도트 렌더 | `imageSmoothingEnabled=false` + **정수 배율** | 도트 뭉개짐 방지 |
| 목표 | 중급 안드로이드 60fps | dt 상한 1/30로 클램프 |

**개발 중엔 `src/index.html`을 그냥 브라우저로 연다.** 빌드는 출고 직전에만 돈다.
선행 사례가 전부 "단일 HTML 직접 편집"이라 1,400줄에서 손을 못 대게 됐던 문제를 여기서 끊는다.

## 3. 게임 상태 설계

### 3-1. 상태머신

```
BOOT ─→ TUTORIAL ─→ BATTLE ⇄ SKILL_PICK ─→ CLIMAX ─→ ULTIMATE ─→ RESULT ─→ ENDCARD
                       ↑__________________|
                    (director가 시간으로 전환. 게임 조건으로 전환하지 않음)
```

**FAIL 상태는 존재하지 않는다.** (S1 계승)
플레이어 HP는 표시되지만 15% 하한에서 클램프된다. 위기감은 주되 죽지 않는다.

### 3-2. 27초 타임라인 (`data/timeline.js`)

| t (초) | 상태 | 내용 | 연출 |
|---|---|---|---|
| 0.0–1.8 | TUTORIAL | 적 3마리 느리게 접근. 자동 사격 즉시 시작 | 손가락 힌트 + "드래그로 이동", **1초 내 첫 킬** |
| 1.8–8.5 | BATTLE 1 | 사방 스폰, 초당 6→14마리 | 킬 카운터 상승, 코인 튐 |
| 8.5–9.7 | SKILL_PICK 1 | **전투를 멈추지 않는다.** 하단에서 카드 3장이 올라오고 0.9초 뒤 자동 확정 | 확정 카드가 하단 슬롯으로 날아가 꽂힘 |
| 9.7–17.0 | BATTLE 2 | 밀도 2배 + 엘리트 2기 | 화면 가장자리 붉은 경고 라인 |
| 17.0–18.2 | SKILL_PICK 2 | 동일 | |
| 18.2–24.0 | CLIMAX | **보스 1기 등장** + 잡몹 80+ | 컷인 · 화면 흔들림 · 카메라 살짝 줌아웃 |
| 24.0–25.5 | ULTIMATE | 게이지 만땅 → **자동 발동, 화면 전멸** | 백색 플래시 → 숫자 폭우 → 코인 폭발 |
| 25.5–27.0 | RESULT | 승리 배너 + 처치 수 카운트업 | |
| 27.0~ | ENDCARD | 키비주얼 + CTA | 아무 곳 탭 = CTA |

**광고 연출 우선순위 대응**
1. 구조 한눈에 → 조작 1종 + 상단 HUD 3요소뿐
2. 속도감 → 적 접근 속도보다 **킬 속도**를 높게. 초당 처치 수가 계속 증가
3. 위기감 → 8~10초, 17~19초 구간에서 화면 가장자리 적 밀도 최대
4. 강해 보임 → 스킬 2회 + 궁극기. 화면당 데미지 숫자 밀도가 3배씩 증가
5. 단순 조작 → 드래그만
6. 최소 UI → 상단 1줄 + 하단 CTA 칩

### 3-3. 안전장치

| 장치 | 값 | 이유 |
|---|---|---|
| HP 하한 | 15% | 사망 없음 (S1). HP는 피격 누적이 아니라 **포위 압력(반경 150px 안 적 수)** 으로 움직인다 — 물량 광고에서 피격 누적을 쓰면 반드시 바닥에 붙는다 |
| 무입력 오토플레이 | 1.2초 | 관망 유저도 완주 (S2) |
| 첫 킬 보장 | 1.0초 이내 | 3초 이탈 방지 (S3) |
| 스킬 자동 선택 | 0.9초 | 카드에서 멈추지 않음. 모달이 아니라 하단 인라인이라 전투가 계속 보임 |
| dt 클램프 | 1/30초 | 백그라운드 복귀 시 순간이동 방지 |
| 리사이즈 | 좌표 재계산만, 게임 리셋 없음 | Dreamy의 "보드 재생성" 문제 회피 |

## 4. 캐릭터 / 적 에셋 구조

### 4-1. `data/character.js` — 교체 지점 1

```js
var CHARACTER = {
  id: 'ranger',  name: '레인저',
  sheet: 'char_ranger',            // 아틀라스 키. 없으면 프로시저럴 폴백

  scale: 3,                        // ★ 정수 배율 (도트 보존)
  anchor: 'feet',                  // 발밑 기준. 알파 자동측정으로 보정
  anim: {
    idle: { row:0, frames:4, fps:6  },
    run:  { row:1, frames:6, fps:12 },
    cast: { row:2, frames:4, fps:14 }
  },
  muzzle: null,                    // null이면 알파 최상단에서 자동 산출 (S6)
  move:   { speed:250, accel:2400 },
  hp:     100,
  attack: {
    type:'projectile',             // projectile | orbit | beam
    dmg:12, rate:0.22, speed:640, range:420,
    count:1, spread:0, pierce:0,
    bullet:{ shape:'arrow', color:'#ffe066', trail:6, size:10 }
  },
  aura: { rim:'#8ef0ff', shadow:0.35 }   // 화면이 복잡해도 주인공이 보이게

```

**주인공 가독성 규칙** — 화면에 200마리가 있어도 중심 캐릭터는 보여야 한다.
1. 플레이어에게만 **림 라이트 1px 아웃라인**
2. 플레이어 발밑 **타원 그림자 + 미세 펄스 링**
3. 적은 채도 낮은 팔레트, 플레이어는 최고 채도
4. 스킬 발동 시 플레이어 주변 반경 60px에 적 스프라이트 알파 0.75

## 6. 캐릭터 교체 방식

### 6-1. 3단계 (아트만 있으면 30분)

```
① src/art/sheets/ 에 새 캐릭터 시트 PNG 를 넣는다
② data/character.js 의 sheet · cell · scale · anim 4개 필드만 고친다
③ python3 tools/build.py   →  dist/playable.html
```

**좌표를 손으로 잡지 않는다.** `sprite.js`가 로드 시점에
- 알파 바운딩 박스를 측정해 **발밑 원점을 자동 정렬**하고
- 여백이 제각각인 시트도 행별로 키를 맞추고
- `muzzle:null`이면 알파 최상단에서 **발사 원점을 자동 산출**한다.

TOY WAR의 `measure()`가 실제로 검증한 방식이다. 캐릭터 3회 재작업 중 좌표 때문에 다시 한 적은 없다.

### 6-2. 교체 검증

```bash
node tools/qa.js          # 기기 10종 · 봇 완주 · 런타임 에러
open dist/playable.html?debug=1   # 히트박스/원점 육안 확인
```

`?debug=1`에서 **발밑 원점 십자선과 히트박스 원**이 함께 표시되므로,
새 캐릭터가 바닥에 떠 있거나 파묻히는 사고를 즉시 잡는다.

### 6-3. IP 통째 교체 (다른 게임용 광고)

| 바꾸는 것 | 파일 | 분량 |
|---|---|---|
| 캐릭터 | `data/character.js` + 시트 1장 | 30분 |
| 몬스터 | `data/enemies.js` + 시트 1~5장 | 1시간 |
| 스킬 이름/아이콘 | `data/skills.js` | 20분 |
| 색·문구·스토어 URL | `data/theme.js` | 10분 |
| 연출 페이싱 | `data/timeline.js` | 필요 시만 |

`src/core/` 와 `src/game/` 은 건드리지 않는다. **이것이 이 구조의 존재 이유다.**
