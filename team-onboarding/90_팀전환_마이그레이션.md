# 90. 팀 전환 마이그레이션 — 실행 체크리스트

> **무슨 문서인가**: 개인이 쓰던 Claude 환경을 팀 전체가 쓰는 환경으로 바꾸는 순서표다.
> **세 갈래를 동시에 옮긴다**: ⓐ 이 저장소를 팀 공용으로, ⓑ GitHub 저장소를 회사 조직 계정으로, ⓒ Claude 요금제를 팀 플랜으로.
> **작성**: 2026-09-11 · **오너**: MX실 실장

## 0. 순서 — 이 차례를 지킨다

세 갈래는 서로 물려 있다. 순서를 바꾸면 두 번 일한다.

```
① Claude 팀 플랜 전환  (좌석이 있어야 팀원이 접속한다)
        ↓
② GitHub 저장소 조직 이전  (주소가 바뀌므로 배포 전에 끝낸다)
        ↓
③ 브랜치 보호 + 팀원 초대
        ↓
④ 저장소 팀 공용화 반영분 배포  ← 이 부분은 이미 끝나 있다 (아래 2번)
        ↓
⑤ 90분 온보딩 세션
```

**왜 이 순서인가**
- 좌석(계정 자리)이 없으면 팀원이 Claude Code를 못 연다. 문서를 아무리 배포해도 실습이 안 된다.
- 저장소를 옮기면 클론 주소(`git clone`에 쓰는 주소)가 바뀐다. 먼저 배포하면 팀원이 옛 주소로 받아 두 번 받는다.

## 1. ⓒ Claude 팀 플랜 전환

> 담당: 실장 + 결제 담당 · 저장소 밖 작업이라 자동화할 수 없다.

### 결정해야 하는 것 (`99_우리팀_규칙.md`에 값을 적는다)
| 항목 | 왜 먼저 정하나 | 상태 |
|---|---|---|
| 좌석 수 | 결제 금액이 여기서 정해진다 | ❓미정 |
| 헤비/라이트 구분 | 코드·자동화를 쓰는 사람만 Claude Code가 필요하다 | ❓미정 |
| 계정 방식 | **개인별 계정 원칙.** 공용 계정은 누가 무엇을 했는지 추적이 안 된다 | ✅ 확정 |
| 결제·비용 담당 | 좌석 추가·해지를 한 사람이 관리해야 중복 결제가 안 난다 | ❓미정 |
| 모델 기본값 | 예산 규칙이 곧 모델 규칙이다 | ✅ Sonnet 기본 (아래) |

### 모델 사용 규칙 (확정)
| 모델 | 언제 | 승인 |
|---|---|---|
| Sonnet | 기본값. 일상 업무 전부 | 불필요 |
| Opus | 긴 제안서, 복잡한 전략, 리서치 4챕터 전체 | 불필요 |
| Fable | 최상위. 대형 수주 제안 최종본 | 실장 승인 |

### 체크리스트
- [ ] 좌석 수 확정 (헤비 N석 / 라이트 N석)
- [ ] 팀 플랜 결제 전환
- [ ] 팀원 개인 계정으로 초대 (회사 메일 주소)
- [ ] 관리자(admin) 2명 지정 — 1명이면 부재 시 아무것도 못 바꾼다
- [ ] `99_우리팀_규칙.md` 1번·5번 항목 채움

## 2. ⓐ 저장소 팀 공용화 — **이 부분은 반영 완료**

개인 기준으로 쓰여 있던 설정을 팀 기준으로 바꿨다. 팀원이 저장소를 열면 전원 같은 기준으로 답을 받는다.

| 무엇을 | 어떻게 바꿨나 | 파일 |
|---|---|---|
| 개인 프로필이 팀 답변에 섞이던 것 | 루트 `CLAUDE.md` 상단을 **팀 기준선**으로 교체. 개인 프로필은 각자 `~/.claude/CLAUDE.md`로 분리 | `CLAUDE.md`, `.claude/library/personal-profile-template.md` |
| 팀 운영 규칙이 없던 것 | 브랜치·민감정보·공유 경계·동시 편집 규칙을 `CLAUDE.md`에 명문화 | `CLAUDE.md` |
| 공용 계정 메일 주소 노출 | 프로젝트 노트에서 주소를 지우고 "사내 위키 참조"로 교체 | `.claude/projects/202608_사내_MAX실AI직무체계/00-note.md` |
| 제안서 덱 시스템 2개가 경합 | `hivelab-proposal-style` 제거. 제안서 덱은 `mx-deck-design` 하나로 통일 | `.claude/skills/mx-deck-design/` |
| 토큰·키가 커밋될 여지 | `.gitignore`에 인증 파일·개인 설정 패턴 추가 | `.gitignore` |
| main 보호 후 노트 유실 위험 | 푸시가 거부되면 `notes/이름-날짜` 구제 브랜치로 밀어 보존 | `.claude/hooks/autosave-project-notes.sh` |

### 결정 완료 — 제안서 덱은 `mx-deck-design` 하나 (2026-09-11, 실장)
제안서 덱 시스템이 둘이면 팀원이 어느 쪽으로 만들지 매번 고른다. 골라야 하는 순간 결과가 갈린다.
- **남기는 것**: `.claude/skills/mx-deck-design/` — MX실 표준. Figma 실측 규격 + `template.html` 동반
- **버리는 것**: `hivelab-proposal-style` — 폴더 구조가 아니라 애초에 작동하지 않았고, 참조하던 원본 파일 2개도 저장소에 없었다
- **되살리려면**: `git show e92fe66:.claude/library/prompts/hivelab-proposal-style.md` (245줄, 이력에 남아 있다)

### ⚠️ git 이력 관련 고지
공용 계정 메일 주소는 **지금 파일에서는 지웠지만 과거 커밋에는 남아 있다.** 저장소를 조직으로 옮기면 그 이력도 함께 간다.
지우려면 이력 재작성(`git filter-repo`)이 필요하고, 그러면 모든 팀원이 다시 클론해야 한다.
판단: 회사 공용 계정 주소라 위험도가 낮다 → **이력은 그대로 두고, 앞으로 넣지 않는 쪽으로 막는다.**

## 3. ⓑ GitHub 저장소 조직 이전

> 현재: `hivelabeud-maker/max` (개인 계정) → 목표: `회사조직/max`
> **소유권 이전은 저장소 소유자만 할 수 있다.** Claude는 권한이 없어 대신 못 한다. 아래 절차는 사람이 실행한다.

### 이전 전에 확인
- [ ] 옮길 조직 계정이 있다 (없으면 GitHub에서 조직 먼저 생성)
- [ ] 본인이 그 조직의 **owner** 권한이다 (member면 이전 대상으로 선택되지 않는다)
- [ ] 열려 있는 브랜치·PR을 정리했다 — 이전 시 함께 넘어가지만, 진행 중인 원격 세션은 끊긴다

### 이전 절차 (사람이 실행)
1. 저장소 → **Settings** → 맨 아래 **Danger Zone** → **Transfer ownership**
2. 새 소유자에 조직 이름 입력 → 저장소 이름 입력해 확인
3. 이전 완료. 옛 주소는 자동 리다이렉트되지만 **영구 보장이 아니다** → 4번을 반드시 한다
4. 이미 클론한 사람은 주소를 갱신한다
   ```bash
   git remote set-url origin https://github.com/회사조직/max.git
   git remote -v   # 바뀐 주소 확인
   ```

### 이전 직후 설정
- [ ] **브랜치 보호** — Settings → Branches → main 규칙 추가
  - `Require a pull request before merging` 켜기
  - 승인 1인 필수
  - (이걸 켜면 위 2번의 구제 브랜치 동작이 작동한다)
- [ ] **팀원 초대** — Settings → Collaborators and teams → Write 권한
  - Admin은 실장 + 1명까지. 전원 Admin은 사고의 원인이다
- [ ] **Claude Code 재연결** — 조직 저장소는 별도 승인이 필요하다
  - 조직 관리자: <https://claude.ai/admin-settings/claude-tag> 에서 저장소 접근 허용
  - 각 팀원: claude.ai → Settings → Connectors → GitHub 재연결
- [ ] 문서 안 저장소 주소 갱신 (아래 명령으로 남은 곳 확인)
  ```bash
  grep -rn "hivelabeud-maker" --include="*.md" --include="*.html" .
  ```

### 되돌리기
이전은 되돌릴 수 있다. 조직 → 개인 계정으로 같은 절차를 한 번 더 하면 된다. 다만 그 사이 생긴 이슈·PR 번호는 유지된다.

## 4. 팀원이 받을 때 (배포 시점에 공지할 3줄)

```bash
git clone https://github.com/회사조직/max.git
cd max
claude          # Claude Code 실행 — CLAUDE.md를 자동으로 읽는다
```

받은 다음 각자 한 번만:
1. `.claude/library/personal-profile-template.md`를 열어 블록을 복사한다
2. 자기 컴퓨터의 `~/.claude/CLAUDE.md`에 붙여넣고 대괄호를 자기 값으로 바꾼다
3. `마케터 돌려 — 아무 카테고리` 로 쳐서 `--- CH1 완료 ---` 줄이 뜨면 설치 정상
