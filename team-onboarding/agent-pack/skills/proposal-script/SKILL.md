# 제안 발표 원고 (Proposal Script)

제안서를 **소리 내어 말하는 문장**으로 바꾼다.
근거는 `.claude/library/proposal-corpus.md` 5절 — 실제 수주 발표 대본에서 뽑은 규칙이다.

> 문서 문장을 그대로 읽으면 발표가 죽는다. 문서는 눈으로 훑는 것이고, 원고는 귀로 따라오게 하는 것이다.
> 이 스킬은 그 번역을 한다.

---

## 시작 전 확인

세 가지가 있어야 원고를 쓴다. 없으면 먼저 채운다.

| 필요한 것 | 없으면 |
|---|---|
| 슬라이드 목록 (번호 · 제목 · 담긴 내용) | 마케터 CH6부터 돌린다 |
| 목표 발표 시간 | 물어본다. 기본값 20분 |
| 발표자가 누구인지 | 물어본다. 오프닝이 발표자에 따라 달라진다 |

---

## 1. 시간 배분부터 한다

원고를 쓰기 전에 **슬라이드마다 초를 먼저 배정**한다. 그래야 분량이 안 터진다.

| 슬라이드 유형 | 배정 | 이유 |
|---|---|---|
| 오프닝 | 30~50초 | 개인 경험 훅 |
| 선언 | 20~30초 | 천천히 읽어야 꽂힌다 |
| 데이터 | 25~40초 | 숫자를 짚어야 한다 |
| 비교·사례 | 18~25초 | |
| 시안 화면 | 12~18초 | 화면이 주역, 말은 거든다 |
| 영상 재생 | 영상 길이 + 5초 | 재생 안내 한 마디 |
| 클로징 | 10초 | |

**실측 기준: 슬라이드당 평균 18.8초** (코웨이 68슬라이드 / 21분 21초).
합계가 목표의 ±10%를 넘으면 슬라이드를 줄이거나 초를 깎는다. 말을 빨리 하는 걸로 해결하지 않는다.

---

## 2. 오프닝 — 개인 경험으로 연다

회사 소개, 감사 인사, 목차 낭독으로 시작하지 않는다.
**발표자가 이 문제를 몸으로 아는 이유**를 먼저 말한다.

### 검증된 구조

```
[1] 인사 + 이름 + 맡은 역할        — 1문장
[2] 개인 경험 — 언제·어디서·무엇을  — 2~3문장, 구체적인 장면
[3] 그래서 이 문제를 안다는 연결     — 1문장
[4] 그래서 이 제안에 임한 태도       — 1문장
[5] 목차 예고                      — 1문장
```

### 실제 사례 (코웨이 BEREX)

> "안녕하세요. 코웨이 BX GUI 디자인 제안을 맡은 김효정입니다.
> 저는 두 아이와 함께 키즈 카페를 가는 일이 많은데, 가끔 키즈 카페에 가면 구석에 놓여진 안마기를 볼 때 굉장히 반가울 수가 없습니다. 그 반가운 이유는 하나죠. 딱 그 순간만큼은 제가 휴식을 취할 수 있는 순간이기 때문인데요.
> 그래서 이 제품도 누군가에게는 간절한 휴식의 순간이라는 걸 알기 때문에, 이번 BEREX가 전달하고자 하는 휴식의 가치도 같이 경험할 수 있는 기회로 만들고 싶다는 생각이 컸습니다.
> 오늘 발표는 시장의 현황부터 시작해서 우리가 정의해야 될 문제, 그리고 이를 해결할 디자인 전략과 최종 디자인 컨셉 순으로 진행하겠습니다."

이 문단이 하는 일은 하나다. **뒤에 나올 페르소나가 책상에서 만들어진 게 아니라는 증명.**

### 발표자 경험이 없을 때

발표자가 그 제품·서비스와 접점이 없으면 지어내지 않는다. 대신 **조사 과정에서 마주친 장면**으로 연다.
> "이번 조사를 하면서 리뷰를 200건 넘게 읽었는데, 그중 한 문장이 계속 걸렸습니다. '기능은 많은데 쓸 줄을 모르겠다.'"

---

## 3. 브릿지 문장 — 장이 바뀔 때마다

슬라이드를 그냥 넘기지 않는다. 다음 장이 왜 필요한지 한 문장으로 잇는다.

### 두 가지 형태만 쓴다

**질문형** — 다음 장이 답이 될 때
> "그렇다면 확인한 사용자들의 기대가 실제 제품 앞에서는 왜 무너지고 마는 것인지, 우리가 직면한 진짜 문제들을 짚어보겠습니다."

**예고형** — 다음 장이 새 재료일 때
> "이러한 분석을 바탕으로, 우리가 집중해야 될 실질적인 기회 요인들을 하나씩 살펴보겠습니다."

### 장 전환 브릿지 표 (A형 7장 기준)

| 전환 | 형태 | 예 |
|---|---|---|
| 개요 → 시장 | 예고 | "그렇다면 우리의 타깃은 누구고 시장은 지금 어떤 모습인지 들여다보겠습니다" |
| 시장 → 페르소나 | 질문 | "그럼 우리는 질문을 던졌습니다. 사용자가 진짜로 원하는 게 무엇인지" |
| 니즈 → 문제 | 질문 | "그렇다면 확인한 기대가 왜 무너지고 마는 것인지" |
| 문제 → 기회 | 예고 | "이러한 분석을 바탕으로 실질적인 기회 요인들을 살펴보겠습니다" |
| 기회 → 트렌드 | 예고 | "이 역할을 수행하기 위해 먼저 산업군 전반의 트렌드를 살펴보겠습니다" |
| 트렌드 → 전략 | 예고 | "그렇다면 어떻게 구현할지 그 전략을 구체적으로 보여드리겠습니다" |
| 전략 → 컨셉 | 예고 | "이제 실제 화면에서 어떻게 보여질지 세 가지 컨셉을 소개해 드리겠습니다" |

**모든 장 전환에 브릿지가 있어야 한다.** 하나라도 비면 원고가 완성된 게 아니다.

## 4. 문장 규칙

### 자문자답으로 전환한다

주장이 바뀌는 자리에서 질문을 먼저 던지고 스스로 답한다.
> "이 프리미엄 브랜드를 소비할 우리의 핵심 타깃은 그러면 누구일까요? 핵심 타깃은 50대 이상의 디지털 네이티브 시니어입니다."

### 숫자 앞에 강조어를 붙인다

문서에 있는 숫자를 읽고 지나가면 안 들린다.
> "**무려** 37년이라는 시간 동안" / "**놀랍게도 무려** 70% 이상의 사용자가" / "**불과** 6개월 만에 18%로 급락합니다"

강조어는 **핵심 수치 3~4개에만** 쓴다. 전부에 붙이면 아무것도 강조되지 않는다.

### 전문 용어는 예를 들어 푼다

슬라이드에는 별표 각주를 달고, **원고에서는 각주를 읽지 않는다.** 대신 아는 사례를 든다.
> 슬라이드: `*소닉 로고: 브랜드 정체성을 3~5초의 짧은 소리로 시각화하는 사운드 인터랙션 기법`
> 원고: "넷플릭스의 두둠 하는 소리, 헤드스페이스의 부드러운 화음처럼"

### 말하는 문장으로 쓴다

| 문서 문장 | 원고 문장 |
|---|---|
| 기능 과잉 문제가 존재함 | 첫 번째 문제는 바로 기능 과잉입니다 |
| 사용 빈도 6개월 후 18% 감소 | 구매 직후 높았던 사용 빈도는 불과 6개월 만에 18%로 급락합니다 |
| 직관적 UI 설계 필요 | 그래서 별도의 이해 없이도 직관적으로 쓸 수 있는 UI 설계가 필요하죠 |

어미를 섞는다 — "~입니다" 만 반복하면 단조롭다. "~하죠", "~인데요", "~거죠"를 끼운다.
한 문장에 생각 하나. 25어절 넘으면 자른다. 길이는 섞는다.

### 영상·시연 안내

> "사용 과정을 담은 프로토타입 영상을 잠시 보시겠습니다."

한 마디만 한다. 영상 내용을 설명하지 않는다.

---

## 5. 클로징

두 문장으로 끝낸다. 요약을 되풀이하지 않는다.

> "이상으로 〔클라이언트〕 〔프로젝트명〕 제안 발표를 마치도록 하겠습니다. 경청해 주셔서 감사합니다."


## 체크리스트

원고를 내기 전에 확인한다.

- [ ] 오프닝이 개인 경험 또는 조사 장면으로 열리는가 (회사 소개로 열지 않았는가)
- [ ] 모든 장 전환에 브릿지 문장이 있는가
- [ ] 총 시간이 목표의 ±10% 안인가
- [ ] 숫자 강조어가 3~4개로 절제되었는가
- [ ] 전문 용어마다 원고용 예시가 있는가
- [ ] 어미가 반복되지 않는가
- [ ] 클로징이 두 문장인가

---

## 가드레일

- **발표자의 개인 경험을 지어내지 않는다.** 없으면 조사 장면으로 대체한다.
- **슬라이드에 없는 주장을 원고에 넣지 않는다.** 발표자가 근거 없이 말하게 만들면 질의응답에서 무너진다.
- **숫자는 슬라이드와 원고가 반드시 일치해야 한다.** 다르면 그 자리에서 신뢰를 잃는다.
- 비유는 쓰지 않는다. 풀이가 필요하면 예를 든다.
