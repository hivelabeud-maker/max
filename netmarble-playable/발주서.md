## 레퍼런스가 무슨 게임인가

받은 자료(영상 2건 + 스틸 3장)에서 이런 단서가 나왔다.

- "기하학적 존재들에게 닿으면 체력이 감소합니다"
- "블랙탄 — 약하지만 빠른 공격속도를 가진 미사일입니다. 수동으로 조작이 가능합니다"
- 적은 발광하는 흰 링, 탄은 흰 물방울형 미사일
- 화면 정중앙에 고정된 코어, 그 둘레를 감싼 점선 궤도
- 웨이브 1/20 → 20/20, Combo 카운터, `스킬 피해 현황` DPS 미터, Lv.1/50 경험치 바
- 마지막에 `CLEAR` → `피해 현황` 3종 + `전리품` 6칸 + 초록 `2배 받기` 버튼

**Geometry Cannon : Idle Defense** (SUPERBOX Inc)다. 스토어 소개문이 장르를 그대로
말해 준다 — *"360-degree tower defense … minimalist geometric visuals with intense
bullet-hell action"*.

> 출처: [QooApp · Geometry Cannon : Idle Defense](https://apps.qoo-app.com/en/app/142920)

## v4 — 배경·캐릭터·탄막 세 가지

실장님 지시 세 줄을 그대로 반영했다. 게임 규칙·타임라인·28초 길이는 손대지 않았다.

| 항목 | v3 | v4 | 방법 |
|---|---|---|---|
| 배경 | 딥 네이비 + 40px 격자 그리드 + 별 170개 | 검정 + 보라 성운 + 별 300개(11%는 붉은 별) | `buildSky()` 로 한 번만 굽는다. 시드 RNG라 열 때마다 같은 별자리 |
| 캐릭터 | 표시 폭 172px | 표시 폭 120px (30% 축소) | `CHARACTER.w` 한 값. 발밑 링과 총구 위치가 이 값에 연동돼 같이 줄어든다 |
| 탄막 | 핑크 다트, 잔상 없음 | 바이올렛 다트 + 보라 잔상 꼬리 | 탄마다 지나온 좌표 3점을 들고 다니며 그라디언트 선으로 잇는다 |
| 발밑 링 | 골드 (#FFB53D) | 네온 보라 | 굵은 바이올렛 헤일로 위에 흰빛 심을 얹는 2패스 |
| 결과창 | CTA + `다시 보기` | CTA 하나 | 문구·탭 영역·핸들러를 함께 걷어냈다 |
| CTA 버튼 | 라임 그린 | 블루 · 기준색 **#6CDBFF** | `ctaButton` 한 함수. 인게임 하단과 결과창이 같이 바뀐다 |
| CTA 등장 | 3.0초에 0.6초 페이드 | 1.2초에 0.22초 페이드 | 광고에서 CTA가 화면에 있는 시간을 1.8초 늘렸다 |
| 보스 | 꽃잎 8장 | 기계 하우징 + 균열 난 에너지 코어 | 장갑판 6장(정회전) + 구동링 3장(역회전) + 코어. 체력이 깎이면 균열이 늘어난다 |
| 결과창 구분선 | CLEAR 아래 가로선 | 없음 | 여백만으로 단락을 나눈다 |
| 피해 게이지 | 고정 폭 420px | 숫자 폭을 재서 자동 | 바 끝과 숫자 사이 여백을 16px로 고정 |

### 보스가 꽃으로 보였던 이유

곡선 꽃잎 8장을 방사로 배치했는데, 그게 정확히 꽃의 정의다.
꽃잎을 각진 도넛 조각으로 바꾸고 회전 속도를 층마다 다르게 준 것이
기계로 읽히게 만든 두 가지다.

| 층 | 반경 | 회전 | 색 |
|---|---|---|---|
| 바깥 장갑판 6장 | 54~76 | `+rot` | 어두운 금속 #0C0A1C + 시안 테두리 |
| 안쪽 구동링 3장 | 41~48 | `-rot × 1.6` | 바이올렛 |
| 에너지 코어 | ~34 | 회전 없음 | 보라 → 핑크 → 어두운 껍데기 |

부품이 다 같은 속도로 돌면 장식이고, 따로 돌아야 기계다.
코어는 아예 안 돌린다 — 껍데기 안에 갇힌 것으로 보여야 하기 때문이다.

### 균열로 남은 체력을 읽게 한 것

균열은 등장할 때 시드 RNG로 6줄을 뽑아 두고, 체력이 깎인 비율만큼
개수를 늘려 보여 준다. 90%면 1줄, 30%면 4줄, 다 깎이면 6줄이 다 벌어진다.

체력 바를 안 봐도 보스가 얼마나 남았는지 형태로 읽힌다.
28초 광고에서 상단 퍼센트 숫자를 읽고 있을 사람은 없다.

균열은 흰 선 밑에 어두운 선을 한 겹 깐다.
코어 안쪽이 밝아서 흰 선만 그으면 중심 쪽 금이 묻힌다.

### CTA 색을 세 값으로 나눠 둔 이유

실장님이 준 건 한 색(#6CDBFF)이지만 버튼은 입체가 있어야 눌리게 보인다.
그래서 같은 색조(hue 195°)에서 밝기만 바꿔 세 값을 만들었다.

| 토큰 | 값 | 쓰임 | 밝기 |
|---|---|---|---|
| `cta` | #6CDBFF | 그라디언트 위 + 발광 | 71% (지정색 그대로) |
| `ctaL` | #B3ECFF | 안쪽 테두리 | 85% |
| `ctaD` | #00B8F5 | 그라디언트 아래 | 48% |

색조가 같아서 버튼 전체는 #6CDBFF 하나로 읽힌다.
색을 또 바꿀 일이 생기면 `cta` 를 갈고 나머지 둘의 밝기만 맞추면 된다.

### 게이지 길이를 재서 정하는 이유

고정 폭 420px로 그려 놓으니 `27k` 처럼 짧은 수치에서 바 끝과 숫자 사이에
80px 가까운 빈 칸이 남았다. 숫자가 오른쪽 끝에 붙어 있어 더 눈에 띈다.

숫자 폭을 재서 바 길이를 역산한다. 다만 두 화면의 규칙이 다르다.

- **결과창** — 수치가 멈춘 화면이라 실제 숫자를 재서 딱 맞춘다
- **인게임** — 수치가 계속 오른다. 실측으로 재면 `9.9k → 10k` 넘어가는 순간
  바 길이가 튄다. 최대 자릿수(`999k`)를 한 번 재서 고정한다

### 발밑 링을 두 번 긋는 이유

골드였을 때는 한 겹으로도 캐릭터가 떴다. 보색에 가까웠기 때문이다.
보라로 바꾸면 배경 성운과 같은 계열이라 한 겹으로는 바닥에 묻힌다.

그래서 네온관처럼 두 번 긋는다. 굵은 바이올렛(#8E5CF7)으로 헤일로를 깔아
자리를 만들고, 그 위에 가는 흰빛(#EADCFF) 심을 얹는다.
네온사인이 유리관 안쪽은 희게, 바깥은 색으로 보이는 것과 같은 구조다.

### 결과창에서 다시 보기를 뺀 이유

플레이어블 광고의 마지막 화면이 할 일은 하나다 — 스토어로 보내는 것.
`다시 보기`는 그 자리에서 시선을 나눠 갖는다. 영상으로 뽑을 때도
결과창에 눌리지 않는 글자가 하나 남는 셈이라 뺐다.

무입력 오토플레이는 그대로다. 다시 보려면 새로고침하면 된다.
녹화 하네스(`?record=1`)의 `window.__reset()` 도 그대로 남아 있다.

### 배경을 이미지로 안 넣고 코드로 그린 이유

이 파일의 팔림새는 "외부 요청 0건 · 100KB"다. 성운 사진을 data URI로 박으면
용량이 서너 배가 된다. 광고 네트워크는 대개 플레이어블에 5MB 안팎의 상한을 두는데,
지금은 여유가 크게 남아 있어야 나중에 캐릭터 프레임을 늘릴 수 있다.

그래서 사진 대신 같은 톤을 코드로 그렸고, 사진을 꼭 써야 할 때를 위해
`BG_IMAGE` 슬롯을 열어 뒀다. 값을 넣으면 구워둔 성운을 그 이미지가 덮는다.

### 잔상을 프레임당 1점으로 잡은 이유

각성 구간에서 화면에 탄이 100발 넘게 남는다. 탄마다 궤적 배열을 새로 만들면
초당 수천 개의 배열이 생겼다 사라진다 — 물량 구간에서 프레임이 떨어지는 원인이 된다.

탄을 만들 때 6칸짜리 배열 하나를 붙여 주고, 매 프레임 그 안에서 값만 밀어 넣는다.
새 배열을 만들지 않으므로 탄이 몇 발이든 비용이 늘지 않는다.

### 탄두 심을 흰색으로 남긴 것

배경이 보라, 탄도 보라라서 중앙에서 탄이 묻힐 수 있다.
탄두 안쪽 34%를 흰색으로 두면 성운 위에서도 탄이 먼저 보인다.

## v3 — 방향을 한 번 잘못 읽었다

"도트형으로 개선해줘"를 **글꼴까지 도트로 찍으라**는 뜻으로 읽고 HUD 텍스트를
전부 픽셀로 만들었다. 아니었다. 실장님이 레퍼런스 화면을 주고 나서야 알았다 —
가리킨 건 **네온 아케이드 디자인 전체**였고, 도트는 캐릭터 아트에만 해당했다.

| | v2 (오독) | v3 (레퍼런스) |
|---|---|---|
| 글자 | 픽셀로 찍은 도트 텍스트 | 매끈한 둥근 볼드 + 글로우 |
| 배경 | 검정 + 코랄 성운 | **딥 네이비 + 격자 그리드** + 별 |
| 강조색 | 코랄 / 마젠타 | **시안 · 핑크 · 퍼플 · 라임 · 골드** |
| 게이지 | 각진 분절 블록 | 둥근 캡 + 안쪽 하이라이트 + 발광 |
| 패널 | 얇은 사각 테두리 | 라운드 패널 + 모서리 다이아 장식 |
| CTA | 코랄 사각 | **라임 그린 라운드 + 십자 장식** |
| 적 | 흰 링 / 육각 | 네온 다이아(시안·아이스·핑크) |
| 탄 | 흰 물방울 | 핑크 네온 다트 |
| 캐릭터 | 그림자만 | 발밑 **골드 링** |

"○○풍으로" 같은 말은 요소 하나를 가리킬 수도, 화면 전체를 가리킬 수도 있다.
레퍼런스 이미지를 먼저 달라고 했으면 한 바퀴를 안 돌았다. 앞으로 톤 지시가 오면
글로만 받지 말고 화면부터 맞춰 보기로 한다.

### v3에서 잡은 버그

- 사각형 헬퍼를 `rr` 로 지었는데 기존 난수 헬퍼와 이름이 같았다. 일괄 치환이
  난수 호출 5곳까지 바꿔버려서 폭발 파티클과 데미지 숫자가 NaN이 됐다. 콘솔에는
  아무 것도 안 뜨고 그냥 안 그려지기 때문에 스크린샷으로만 잡힌다.
- HP 피격 플래시 문턱이 0.4라 **타임라인 감소에도 매 프레임 발동**해 체력 바가
  계속 흰색이었다. 문턱을 6으로 올려 실제 피격에만 반응하게.
- 각성 구간에 노바만 폭주해 피해 현황이 12k / 9.5k / **118k** 로 무너졌다.
  쿨다운·계수를 조정하고 마지막 일격 피해를 균등 분배.

## v2 — 무엇이 달라졌나

v1은 그대로 두고 새 폴더로 올렸다. 되돌릴 자리가 있어야 한다.

| 항목 | v1 | v2 |
|---|---|---|
| HUD | DOM + 매끈한 시스템 폰트 | **전부 캔버스 도트** — 리타 픽셀아트와 톤 일치 |
| 스킬 해금 안내 | "섬광 해금 —" 토스트 | 텍스트 없음. 아이콘 점멸 + 펀치로만 |
| 각성 이후 | 스폰 정지 → 빈 화면에 대고 사격 | 20/초로 계속 몰려옴 |
| 엔딩 | 그냥 CLEAR로 전환 | **마지막 일격**(25.0초) → 전멸 → `ALL CLEAR` → CLEAR |
| 표적 없을 때 | 계속 발사 | 발사 중지 (멈춘 것처럼 보이던 원인) |
| HP 곡선 | 1000 → 640 (변화가 안 보임) | 1000 → 380 + 피격 시 게이지 끝단 백플래시 |
| 게이지 | 연속 바 | 잔 도트 분절 — 블록이 하나씩 사라져 변화가 읽힌다 |

### 도트 UI를 폰트 파일 없이 만든 법

외부 요청 0건이 제약이라 픽셀 폰트를 실을 수 없었다. 대신 **작게 그린 글자를
알파 0/255로 잘라 안티에일리어싱을 없앤 뒤 정수배로 확대**한다. 한글도 그대로
도트가 되고, 용량은 0KB다. (`pxLabel` / `pxText`)

한 번 크롬을 두껍게 잡았다가 되돌렸다. 3px 흰 테두리 + 하드 오프셋 그림자 +
굵은 분절 바로 갔더니 90년대 UI로 읽혔다. 도트를 쓴다고 크롬까지 옛날 것을
쓸 이유는 없다 — **타이포만 도트로 두고 테두리·그림자는 걷어내야** 요즘 픽셀
게임 UI가 된다.

### 녹화 모드

실제 플레이어블로 배포하는 게 아니라 **녹화해서 엔드카드에 붙이는 용도**라
프레임 스텝 하네스를 넣었다. `?record=1` 로 열면 rAF 대신 `window.__step(dt)` 로
한 프레임씩 전진한다. 시드 RNG + 고정 dt라 몇 번을 돌려도 같은 영상이 나온다.

- 화면비: **9:16** (BASE 720×1280, 스케일 상수 1개 → 1080×1920)
- 산출: `netmarble_playable_v3_1080x1920.mp4` (H.264 · 30fps · CRF 18 · 17MB)
- 보스 폭발 연출도 `setTimeout` 에서 게임 시각 타이머로 바꿨다. 프레임 스텝에서
  `setTimeout` 은 안 돌아서 녹화본에만 연출이 빠지는 사고가 난다.

## 교체 슬롯 — 넘길 때 여기만 만지면 된다

v3 `index.html` 상단에 두 개가 나란히 있다.

| 슬롯 | 위치 | 지금 값 | 교체 방법 |
|---|---|---|---|
| 중앙 캐릭터 | `CHARACTER.frames` | 리타 8프레임(dataURI) | 배열만 교체. `w`로 크기, `fps`로 속도 |
| 스토어 링크 | `CTA_URL` | `STORE_URL_HERE` | **필수 교체.** 미교체 시 CTA가 동작 안 함 |

캐릭터는 **회전시키지 않고 좌우 반전만** 한다. 픽셀아트를 각도로 돌리면 계단이
뭉개져서다. 조준이 왼쪽이면 뒤집고, 사격 방향은 캐릭터 몸이 아니라 궤도 위의
시안 조준 마커가 따로 알린다.

광고 네트워크가 자체 랜딩 처리를 쓰면 `window.playableCTA` 를 정의해 두면 된다.
그쪽이 있으면 `window.open` 대신 그리로 넘어간다.

## 만들면서 걸린 것 — 다음 프로젝트로 넘길 것

### 1. 프레임을 깎은 건 이펙트가 아니라 전면 채우기였다

물량 구간에서 프레임이 떨어져서 원인을 세 갈래로 나눠 실측했다.

| 조건 | FPS |
|---|---|
| 원본 | 10.9 |
| shadowBlur 전면 제거 | 12.0 |
| 동시 개체 58 → 20 | 11.6 |
| **DPR 2 → 1** | **47.5** |

이펙트도 개체 수도 아니고 **픽셀 채우는 비용**이 지배적이었다. 배경·성운·별밭을
한 장으로 구워 blit 1회로 줄이고 DPR을 1.5로 묶어 10.9 → 25~27 FPS.
(소프트웨어 렌더링 기준. 실기기는 GPU 가속이라 더 나온다.)

> 다음부터 플레이어블 성능이 안 나오면 **이펙트부터 걷어내지 말고 DPR과 전면
> fillRect 횟수부터 센다.** 순서를 거꾸로 잡으면 연출만 잃고 프레임은 그대로다.

### 2. dt를 캡하면 광고 길이가 늘어난다

프레임 튐을 막으려고 `dt`를 0.05로 캡했더니, 무거운 구간에서 게임 시각이 실시간보다
3초 뒤처져 각성 비트가 제때 안 왔다. 저사양 기기에서 28초짜리가 31초가 된다는 뜻이다.

→ **타임라인은 실경과시간으로, 물리만 캡한다.** 1층(광고 껍데기)에 그대로 남길 규칙.

### 3. 무패 구조는 충돌 결과에 맡기면 안 된다

처음엔 적이 코어에 닿아야 HP가 깎이게 짰는데, 오토플레이가 너무 잘 막아서 28초
내내 HP가 1000/1000이었다. 긴장 축이 화면에 안 보인다.

→ HP·SHIELD도 **타임라인이 지배**하게 바꿨다. 충돌은 그보다 더 깊게만 팔 수 있고
회복은 없으며 하한은 클램프. 양식의 "타임라인이 상태를 지배하고 게임 조건이
지배하지 않을 것"은 몹 스폰뿐 아니라 **체력 게이지에도 적용된다.**

### 4. 픽셀아트를 팔레트 압축할 땐 알파가 먼저 깨진다

리타 8프레임을 64색으로 줄여 용량을 117KB → 53KB로 절반 넘게 깎았는데,
`quantize(MEDIANCUT)` 뒤에 투명 인덱스를 따로 칠하는 방식은 팔레트 밖 인덱스를
참조해 **캐릭터 뒤에 검은 사각형**이 남았다. 스크린샷을 안 봤으면 그대로 나갔다.

→ RGBA를 그대로 양자화하는 `FASTOCTREE`를 쓰고, **압축 직후 좌상단 픽셀의 알파가
0인지 코드로 검증**한다. 용량은 같고 알파는 산다.

### 5. 광고는 뷰포트를 꽉 채워야 한다

`Math.min` 스케일(contain)로 맞췄더니 390×844 화면에서 위아래 각 75px, 화면의 18%가
검은 띠였다. 데스크톱 비율에서는 안 보여서 모바일을 안 찍었으면 놓쳤다.

→ 스테이지 바깥 배경을 게임 성운과 이어지는 그라디언트로 깔아 경계를 지웠다.
**플레이어블 검수는 반드시 390px에서 눈으로 본다.**

### 6. 점으로 시작하는 폴더는 Netlify가 배포하지 않는다

`.claude/projects/...` 에 HTML을 두고 링크를 주면 404다(실측). `/docs/maxos/` 는 200.
지금까지 이 경로로 링크를 안내해 온 게 있으면 전부 안 열렸을 것이다.

→ **브라우저로 열어야 하는 산출물은 `docs/` 아래**, 실무 추적용 문서만 `.claude/projects/`.
링크를 뽑기 전에 `curl -o /dev/null -w "%{http_code}"` 로 한 번 찍어 본다.

### 7. 계속 움직이는 버튼은 탭 타깃이 아니다

CTA에 `transform: scale` 펄스를 걸었더니 자동 QA가 "element is not stable"로
클릭을 못 했다. 사람 손가락은 눌리지만, 클라이언트가 돌리는 검증 스크립트는 막힌다.

→ 펄스는 가상요소 헤일로에만 걸고 버튼 박스는 고정한다. 탭 영역도 실측 25px에서
44px로 올렸다(iOS HIG · WCAG 2.5.5).

## 검수 이력

`design-critique` 게이트 1회 통과 후 🔴 항목 반영. 주요 수정:

- `<!DOCTYPE>` · `<meta charset>` 누락 → WebView 인라인 주입 시 한글 깨짐 위험이었다
- CTA에 제작사 URL이 하드코딩돼 있던 것 → 슬롯으로 분리
- 모바일 실측 폰트 5.4px(스킬 Lv 배지) → 최소 12px 이상으로 상향
- 스킬 수치 대비 2.3:1 → 바 밖으로 빼서 항상 흰 글씨
- 토스트가 HP/SHIELD 라벨을 19px 덮던 것 → 위로 이동
- 결과창 투과로 같은 수치가 두 번 보이던 것 → 인게임 HUD 페이드아웃
- 보스 HP 바가 총알·팝업에 관통당하던 것 → 상단 고정 배너로 분리
- 손 가이드가 실제 조작과 정반대를 가리키던 것 → 조준각에 종속
