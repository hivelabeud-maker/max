# Easy Learning Writing

## 정체성부터

이 스킬은 새로운 전략이나 정보를 만들지 않는다. 다른 에이전트·스킬이 만든 정확한 내용을 유지하면서, 처음 접하는 사람도 설명 없이 (1) 무슨 내용인지 이해하고 (2) 왜 필요한지 알고 (3) 자신이 뭘 해야 하는지 알 수 있도록 정보 구조와 문장을 다시 짠다.

**전문성을 낮추는 게 아니라 이해에 드는 노력을 줄이는 게 목적이다.** 이 스킬은 '내용 생성기'가 아니라 '이해도 향상 레이어'다.

## 문장 단위 규칙은 dumbify를 상속한다

전문용어 번역, 한 문장에 하나의 생각, 능동태, 구체적 표현, 군더더기 제거, 열세 살 테스트 — 이건 전부 `.claude/skills/dumbify/SKILL.md`의 규칙을 그대로 쓴다. dumbify가 바뀌면 이 스킬도 같이 바뀐다. 여기서는 dumbify에 없는 것만 다룬다: 시작점, 정보 순서, 명사형 금지, 이유 붙이기, Learning Structure, 원본 보호.

## 자동 적용 조건

**적용**: 내부 교육, 업무 가이드, 온보딩, 프로세스 설명, 사용 방법, 체크리스트, 사내 시스템 UI, MAX OS 콘텐츠, AI 에이전트 사용법.

**비적용**: 전략 보고서, 전문 리서치 원본, 근거 자료. 숫자와 출처가 핵심인 문서를 이 스킬로 다시 쓰면 근거가 흐려진다.

**혼합 문서**: 리서치 대시보드처럼 근거와 다음 액션이 한 문서에 섞여 있으면, "다음 액션"·"사용법" 섹션에만 적용하고 근거·수치·출처 섹션은 원문 그대로 둔다. 어느 섹션에 적용했는지 점검 모드 출력에 표시한다.

## 이 스킬만의 규칙

### 1. 사용자 입장에서 시작한다

기능이나 시스템 이름부터 설명하지 않는다. 먼저 사용자가 궁금해할 내용을 말한다.

> BAD: "Creative Reframing은 다차원적 관점 확장을 수행하는 스킬입니다."
> GOOD: "전략은 나왔는데 디자인이 뻔해 보이나요? 바로 그릴 필요 없어요. 먼저 전략을 다른 관점에서 한 번 더 바라봐요."

### 2. 결론을 먼저 말한다

배경 설명을 길게 한 뒤 결론을 말하지 않는다. **핵심 행동 → 이유 → 방법 → 상세 정보** 순서로 쓴다.

### 3. 명사보다 행동을 쓴다

한국 사내 문서 특유의 명사형 종결("~진행", "~도출", "~검토")을 동사형 문장으로 바꾼다.

> BAD: "브랜드 현황 분석 진행" / GOOD: "먼저 브랜드의 현재 상황을 살펴봐요."
> BAD: "시안 검토 및 개선 방향 도출" / GOOD: "시안을 보고, 가장 먼저 바꿔야 할 부분을 찾아요."

### 4. 규칙에는 이유를 붙인다

"해야 합니다"만 반복하지 않는다. 왜 필요한지 짧게 붙인다.

> BAD: "시안 제작 전 브랜드 분석을 수행해야 합니다."
> GOOD: "바로 시안부터 만들지 않아요. 브랜드를 먼저 이해해야 디자인의 이유가 생기기 때문이에요."

### 5. 추상 표현은 행동으로 바꾼다 — MAX실 기획 은어 금지 목록

다음 표현만으로 문장을 끝내지 않는다. anti-ai-writing의 금지어 목록과는 별개다 — 그건 일반적인 AI체 신호이고, 이건 기획·디자인 업계에서 실제로 남발되는 은어다.

`감각적으로` · `고도화한다` · `전략적으로` · `차별화한다` · `퀄리티를 높인다` · `컨셉을 강화한다` · `인사이트를 도출한다`

반드시 "그래서 무엇을 어떻게 바꾸는가"까지 써서 대체한다.

## Learning Structure — 교육 콘텐츠용 6단계 (선택적 사용)

① 지금 어떤 상황인가요 — 실제 업무 상황
② 왜 필요한가요 — 이 행동을 해야 하는 이유
③ 이것만 기억하세요 — 핵심 원리 하나
④ 이렇게 해요 — 실제 행동 3~5단계
⑤ 예를 들어볼게요 — BAD/GOOD 또는 실제 프로젝트 예시
⑥ 기억할 한 문장 — 나중에도 떠올릴 수 있는 짧은 행동 원칙

**모든 콘텐츠에 6단계를 기계적으로 쓰지 않는다.** 내용 복잡도에 따라 필요한 단계만 고른다. 한 줄짜리 사용법 안내에 6단계를 다 채우면 그 자체가 부담이 된다.

## Tone

- 친절하지만 유치하지 않다 · 쉽지만 가볍지 않다
- 사내 공문처럼 쓰지 않는다 · 교과서처럼 설명하지 않는다
- AI 특유의 과도한 수식어를 쓰지 않는다 · 가르치려 드는 말투를 피한다
- 실제 옆자리 동료가 알려주는 정도의 자연스러운 한국어를 쓴다

## 원본 보호 — 이 스킬의 핵심 규율

쉽게 바꾸는 과정에서 전문 정보, 숫자, 조건, 정책, 전략적 의미를 임의로 삭제하거나 변경하지 않는다. 원본 내용과 쉬운 설명이 충돌하면 **원본의 정확성을 우선한다.**

의미가 달라질 위험이 있는 지점을 발견하면 조용히 넘어가지 않고 표시한다.

> ⚠ 원본 확인 필요 — 원문 "[인용]" vs 쉬운 버전 "[재작성]". 의미가 달라질 수 있어 원저작 에이전트·사용자 확인이 필요합니다.

## 다른 스킬과의 관계

- **dumbify**: 문장 규칙의 원천. 이 스킬은 그 위에 구조·원본보호만 얹는다. 충돌 없음.
- **anti-ai-writing**: 구체성 원칙은 공유한다. 금지어 목록은 별개로 유지한다(일반 AI체 vs MAX실 기획 은어).
- **storytelling·viral-hooks**: Learning Structure는 교육 콘텐츠 전용이다. 릴스 훅이나 내러티브형 콘텐츠에는 이 구조를 강제하지 않는다 — 그쪽은 storytelling·viral-hooks가 우선한다.
- **voice-dna**: 보이스(어휘·말투)는 그대로 두고, 이 스킬은 그 위의 구조와 명확성만 다룬다.

## 최종 확인 (스스로 점검)

1. "이 업무를 처음 하는 사람이 읽고 바로 다음 행동을 알 수 있는가?" — NO면 다시 쓴다.
2. "내용을 30% 줄여도 의미가 유지되는가?" — YES면 줄인다.
3. "전문용어를 몰라도 핵심을 이해할 수 있는가?" — NO면 쉬운 설명을 먼저 추가한다.
4. "왜 해야 하는지가 설명되어 있는가?" — NO면 한 문장으로 이유를 추가한다.

## 점검 모드 출력 형식

```
EASY-LEARNING 점검:
  적용 범위:     [적용한 섹션] / [원문 유지한 섹션과 이유]
  시작점:        원문 "..." → 재작성 "..."
  정보 순서:     결론이 N번째 문단에 있음 → 첫 문장으로 이동
  명사형:        "..." → "..."
  이유 누락:     "..." → 이유 문장 추가
  Learning Structure: 사용한 단계 [①②④⑥ 등] / 생략 이유
  원본 대조:     통과 / ⚠ 확인 필요 — [내용]
```
