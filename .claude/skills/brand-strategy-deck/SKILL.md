# Brand Strategy Deck — 리서치·전략 HTML 생성 스킬 (STEP 18)

리서치·전략(01~12 산출물)을 **매 프로젝트 같은 구조·같은 디자인**의 `deck.html`로 출력한다.
디자인은 프로젝트마다 새로 짜지 않는다. `render.py`가 `report-data.json`을 읽어 자동으로 만든다.

## 참조 파일 (반드시 먼저 읽기)
| 파일 | 용도 |
|---|---|
| `REPORT_SCHEMA.md` | 대시보드 11개 뷰 구조 + `report-data.json` 골격 + 최소 통과 기준 |
| `COMPONENTS.md` | 대시보드 컴포넌트 목록(카드·표·맵·점수바 등) |
| `template.html` | 좌측 네비게이터형 대시보드 셸(모노톤+포인트 4색 CSS 포함) |
| `render.py` | **`report-data.json` → `deck.html` 자동 렌더러.** CLI로 직접 실행 |
| `references/grain-golden-example.html` | 참고용 — 이전 세대 스크롤형 골든(정보 밀도·출처 표현 판단 기준) |
| `references/maxos-golden-example.html` | 16:9 슬라이드 포맷이 필요할 때 별도 참조 |
| `references/boomi-golden-example.html` | (원본 확보 시 교체 · 현재 stub) |

## 생성 절차 (자동 · render.py)
HTML은 손으로 슬롯을 채우지 않는다. **`report-data.json`이 완성되면 `render.py`가 결정론적으로 `deck.html`을 만든다.** 이래야 매 프로젝트 같은 구조·같은 문체·같은 색 규칙이 자동으로 나온다.

1. **원본 확인** — `outputs/01~12` + `report-data.json` 존재 확인. 없으면 marketer/해당 스킬로 되돌림.
2. **누락 필드 확인** — `report-data.json`을 `REPORT_SCHEMA.md` 골격과 대조.
3. **게이트 검증** — `quality-gate` 스킬 기준 통과 확인(경쟁 30+, 이종 30+, 출처, 축 근거, 화이트스페이스 기회/함정, 자산×기회 연결). 미달 시 HTML 완성 처리하지 않고 추가 조사.
4. **★ 글쓰기 필터 (필수)** — `report-data.json`에 넣는 모든 문장(observation·why·tension·opportunity·one_line·positioning 등)을 `anti-ai-writing` + `dumbify` 스킬로 먼저 통과시킨다. render.py는 데이터를 그대로 옮길 뿐 문장을 다듬지 않으므로, **문장 품질은 JSON을 채우는 이 시점에 확정**한다. 아래 "글쓰기 규칙" 참조.
5. **자동 렌더** — 아래 명령 한 줄로 생성한다:
   ```bash
   python3 .claude/skills/brand-strategy-deck/render.py <프로젝트경로>/outputs/report-data.json <프로젝트경로>/deck.html
   ```
   `template.html`(좌측 네비게이터형 대시보드)에 데이터를 채워 넣는다. 경쟁사 30+ · 이종업계 30+ 카드, 포지셔닝 맵, 화이트스페이스, 전략 대안·추천까지 전부 자동 렌더링된다.
6. **출처 확인** — 콘솔 출력(`경쟁 N개 · 이종업계 N개 · 출처 N건`)으로 카운트가 목표(30+/30+)를 채우는지 확인.
7. **반응형·구조 점검** — 브라우저로 열어 좌측 네비게이터(00~10) 클릭 이동, 표 필터·검색, 860px 이하 모바일 전환을 확인. `deck.html`을 파싱해 미충전 슬롯(`{{`)이 0인지, div/section 태그가 짝이 맞는지 검사한다.

## 화면 구조 — 좌측 번호 네비게이터형 대시보드
스크롤 내려 읽는 리포트가 아니라, **좌측에서 원하는 판단 지점으로 바로 이동하는 대시보드**다. 상단 탭은 구분이 잘 안 보인다는 피드백에 따라 폐기했다.

```
00 요약 대시보드   — 핵심 지표 4개 + 진행 파이프라인 + 추천 결론 한눈에
01 브리프·문제 정의 — 클라이언트 요청 → 재정의한 진짜 문제
02 브랜드 팩트북    — 자산·격차·타깃
03 경쟁 리서치      — 30+ 브랜드 표(유형 필터·검색)
04 포지셔닝 맵      — 축 후보 → 선정 축 → 좌표
05 화이트스페이스   — 기회 vs 함정
06 이종업계         — 30+ 사례 표 + 차용/변환/회피
07 핵심 인사이트    — 관찰 → 긴장 → so what
08 전략 대안        — 옵션별 점수바 비교
09 추천 전략        — 원칙·로드맵·하지 않을 것·리스크
10 출처·근거 추적   — 전체 출처 목록
```
데스크톱은 사이드바 고정, 740px 이하에서는 상단 가로 스크롤 필 바로 전환된다(`template.html` 미디어쿼리).

## 색 규칙 — 모노톤 + 포인트 4색
기본 무드는 **모노톤**(`--bg #f2f1ee`, `--ink #161616`, `--accent #1a1a17` 등 회색·검정 계열)이다.
아래 4색은 **분류·상태 구분이 꼭 필요한 곳에만** 쓴다. 장식으로 쓰지 않는다.
| 색 | 용도 |
|---|---|
| `#2e53f9` 블루 | 출처 등급 T1, 핵심 정보(선정된 축·재정의된 문제), 링크, Evidence ID |
| `#c5ff79` 라임 | 출처 등급 T2, 화이트스페이스 기회, 이종업계 Borrow, 전략 점수 강조 |
| `#ff86f6` 핑크 | 출처 등급 T3, 리스크 중간 단계 |
| `#ff6e23` 오렌지 | 출처 등급 T4(미검증), 화이트스페이스 함정, 리스크 높음, 하지 않을 것(no-card), 이종업계 Avoid |

새 분류가 필요해도 다섯 번째 색을 만들지 않는다. 위 4색 중 의미가 가장 가까운 것을 고르거나, 모노톤으로 남긴다.

## 글쓰기 규칙 (자동 적용 · anti-ai-writing + dumbify)
덱은 심사위원이 아니라 사람이 읽는다. 카드 한 장도 아래를 지킨다.
- **본문은 중2, 제목은 초6 읽기 난도.** 어려운 한자어 대신 쉬운 우리말(상이하다→다르다, 명시→적다).
- **한 문장 한 생각.** 절이 겹치면 쪼갠다. `A·B·C·D` 식 압축 나열로 문장을 대신하지 않는다.
- **구체성 레벨 3+.** 범주어("니치 과밀", "구조적 한계")는 사례·숫자·행동으로. 예: "니치가 많다" → "브랜드 12개가 같은 미니멀 화이트를 쓴다".
- **금지**: 부정 병렬("단순히 X가 아니라 Y"), 죽은 도입부, 의미 부풀리기(핵심·중대·혁신적), 빌려온 컨설팅 톤, 줄표(—) 남발.
- **카드는 라벨+짧은 평서문.** 명사 나열 카드라도 각 항목은 읽고 바로 이해되게. 약어·전문어는 처음 등장 시 한 번 풀어준다.
- 점검: 문장을 소리 내어 읽어 걸리면 쪼갠다. `anti-ai-writing` 점검 모드로 최종 패스.

## 절대 규칙
- **디자인 재발명 금지.** `template.html`의 카드·표·네비게이터 구조를 프로젝트마다 새로 짜지 않는다.
- **정보 밀도 유지.** HTML용으로 새로 요약해 축소하지 않는다. 표는 필터·검색으로 탐색 가능하게.
- **출처 없는 수치·단정 금지.** 없으면 "추정/미확인"(T4) + 검증 대상 표시.
- **화이트스페이스는 기회와 함정을 함께.**
- **추천 전략은 브랜드 자산과 시장 기회를 연결.**
- 데이터는 `report-data.json`이 정본. HTML에만 데이터를 두지 않는다.
- 색은 위 4색 표를 벗어나지 않는다.

## 빠른 시작
```bash

  .claude/projects/<YYYYMM_PROJECT>/outputs/report-data.json \
  .claude/projects/<YYYYMM_PROJECT>/deck.html
```
