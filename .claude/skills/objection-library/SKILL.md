# 반론 라이브러리

제안서를 다 만든 뒤, 발표 전에 돌린다. `critic`·`review-panel`이 찾은 약점이 여기 재료가 된다.

원칙: **진단이 먼저다.** 상대가 무엇을 걱정하는지 모르는 채 답하면 그 카드는 실패다.

- 반박: "비싸다" → "다른 고객사도 처음엔 그러셨는데 ROI가 3배였습니다"
- 진단: "비싸다" → "무엇과 비교해서 비싼가요 — 작년 집행액인가요, 아니면 지금 잡혀 있는 예산 라인인가요"

진단 질문 하나가 답변 열 개보다 낫다.

## 절차

### 1. 반론을 모은다
출처를 구분한다.
- RFP·질의응답 문서에 실제로 적힌 것
- 지난 제안에서 받은 질문 (`.claude/projects/` 노트)
- `critic`·`review-panel`이 지적한 약점
- 경쟁사가 우리를 공격할 지점

들은 적 없는 반론을 지어내지 않는다. 추정이면 추정이라고 적는다.

### 2. 뿌리로 묶는다
표면 문구가 달라도 뿌리가 같으면 한 카드다.
- 가격 뿌리: 예산 부족 / 가치 불신 / 비교 대상 오류
- 신뢰 뿌리: 사례 부족 / 인력 규모 / 유사 업종 경험
- 실행 뿌리: 일정 / 리소스 / 유지보수
- 내부 뿌리: 결정권자가 따로 있음 / 기존 벤더와의 관계

### 3. 우선순위
빈도가 아니라 **딜 영향도**로 먼저 정렬한다. 한 번 나왔지만 계약을 깨는 반론이 다섯 번 나온 잔소리보다 위다.

### 4. 카드를 쓴다
카드마다 5단계 경로를 채운다.

| 단계 | 내용 |
|---|---|
| 인정 | 상대 말을 되돌려준다. 방어하지 않는다 |
| 진단 | 질문 1~2개. 무엇과 비교하는지, 누가 걱정하는지 |
| 답변 | 진단 결과에 따라 갈라지는 답 |
| 증거 | 숫자·사례·포트폴리오. 출처와 최종 확인일을 단다 |
| 다음 단계 | 이 대화를 어디로 끌 것인가 |

### 5. 하지 말 것과 에스컬레이션
- 하지 말 말: 확정 안 된 일정 약속, 근거 없는 경쟁사 폄훼, 확인 안 된 단가
- 넘길 사람: 법무 / 견적 / 일정 확약은 실장 판단으로 올린다

## 출력 템플릿

```markdown
## 반론 우선순위
| 순위 | 반론 | 뿌리 | 딜 영향 | 근거 출처 |
|---|---|---|---|---|

## 카드
### OBJ-01. "{상대가 실제로 할 법한 말}"
- 뿌리:
- 인정: 
- 진단 질문: 1) 2)
- 답변 A ({진단 결과 1}일 때):
- 답변 B ({진단 결과 2}일 때):
- 증거: {내용} · 출처 · 최종 확인일
- 다음 단계:
- 하지 말 말:
- 에스컬레이션:

## 근거 대장
| 증거 | 승인 상태 | 소유자 | 최종 확인일 |
|---|---|---|---|
```

## 품질 게이트
- 카드마다 진단 질문이 있는가
- 증거에 출처와 확인일이 붙었는가
- 지어낸 반론을 실제 반론처럼 적지 않았는가
- 딜을 깨는 반론이 위에 있는가
