# MX Research Dashboard Design — 마케터 산출 표준 시스템 (탭형)

`mx-deck-design`(슬라이드 덱)의 짝 스킬. **덱은 위→아래 스크롤, 대시보드는 좌측 탭 클릭으로 뷰 전환.**
좌측 사이드바(nav) + 12뷰 탐색형 구조의 리서치·전략 대시보드 HTML을 만드는 시각 시스템.
**목표: 마케터가 뭘 조사하든 항상 같은 12뷰 구조로 나오게.**

## 이름으로 구분하기

| 스킬 | 좌측 구조 | 상호작용 |
|---|---|---|
| `mx-deck-design` | 없음(슬라이드가 순서대로) | 위→아래 스크롤 |
| `list-deck-design` | 앵커 목차(220px) | 클릭 시 그 섹션으로 스크롤 이동 |
| **`mx-research-dashboard-design`** (이 스킬) | **nav-item 12개 탭** | **클릭 시 뷰가 통째로 전환(다른 뷰는 숨김)** |

## 언제 쓰나

- 마케터 에이전트가 "리서치 쭉 돌려줘" / "마케터 돌려" 결과를 문서로 낼 때 (자동 적용)
- 브랜드 현황 조사 → 진단 → 문제 정의 → 발산까지의 전체 흐름을 한 파일로 추적하고 싶을 때
- 리더 승인·팀 검토용으로 "결론 먼저, 근거는 필요할 때 펼쳐 보기" 형태가 필요할 때

쓰지 말 것: 발표용 슬라이드 덱(그건 `mx-deck-design`), 에디토리얼 리포트(그건 `list-deck-design`).

## 구조 — 12뷰 (마케터 4챕터 → 1:1 매핑)

| 뷰 | 내용 | 마케터 챕터 |
|---|---|---|
| 00 요약 대시보드 | 결론 먼저 + 진행 파이프라인 + 핵심 지표 4칸 | 종합 |
| 01 브리프·문제 정의 | 요청(client request) → 진짜 결정 문제로 재정의 | 0 RFP · CH3 |
| 02 브랜드 팩트북 | 대상 브랜드 사전 이해 | CH1 |
| 03 경쟁 리서치 | 경쟁 브랜드 표 + 출처 (보통 30개 기준) | CH1 |
| 04 포지셔닝 맵 | 축·좌표 근거, XY 포지셔닝 | CH2 |
| 05 화이트스페이스 | 빈자리 기회/함정 판정 | CH2 |
| 06 이종업계 | 타 업계 차용 사례 (보통 30개 기준) | CH1 |
| 07 핵심 인사이트 | 패턴·긴장·So What | CH2→CH3 |
| 08 브랜드 밸류 키워드 | 가치 키워드 도출 | CH3 |
| 09 전략 대안 | 방향 후보 비교·점수 (보통 3안) | CH4 |
| 10 추천 전략 | 추천안 + 실행 원칙 + 하지 않을 것 | CH4 |
| 11 출처·근거 추적 | 전체 출처 티어(T1~T4) 분류 | 전 챕터 |

**00 요약과 11 출처 추적은 절대 생략하지 않는다.** 나머지는 프로젝트 성격에 맞게 가감 가능
(예: RFP가 없으면 01 브리프를 축소, 이종업계 조사가 없으면 06 생략).

## 내용 품질 규칙 (레이아웃보다 먼저 지킨다)

### 1. 어려운 말은 풀어 쓴다 — 초등 5학년 기준

전문 용어는 **지우지 말고 뜻을 붙인다**: `용어(쉬운 풀이)` 형식.

- ❌ "화이트스페이스를 공략" → ⭕ "**화이트스페이스**(빈자리 — 아무도 안 하고 있는 자리)를 노림"
- ❌ "CAGR 12%" → ⭕ "해마다 평균 12%씩 성장(**CAGR** = 연평균 성장률)"

**02 팩트북 뷰 하단에 「이 문서에 나온 말 풀이」 표를 반드시 넣는다.**
`용어 | 쉬운 뜻 | 이 문서에서 쓰인 곳(뷰 번호)` 3열. 같은 용어는 여기서 한 번만 풀고,
본문에서는 처음 나올 때만 괄호를 붙인다.

문장 규칙: 한 문장에 생각 하나(25어절 넘으면 자름), 길이는 섞어서, 비유는 기본 0개.

### 2. 출처는 티어를 달고, T4는 본문에서 뺀다

| 티어 | 색 | 무엇 |
|---|---|---|
| T1 | blue | 1차 자료 — 통계청·KOSIS, 상장사 IR, 공식 발표, 정부·협회 통계 |
| T2 | lime | 검증된 2차 자료 — 주요 언론, 유료 리서치 리포트, 학술 논문, 어워드 |
| T3 | pink | 참고용 — 업계 블로그, 리뷰·커뮤니티 원문(소비자 언어 수집용이면 유효) |
| T4 | orange | **본문 사용 금지** — 출처 불명 요약글, 콘텐츠팜, AI 생성 요약, 광고성 보도자료 |

- 모든 숫자에 **기준연도 + 출처 URL + 티어**를 붙인다. "크게 성장" 같은 문장은 쓰지 않는다.
- 핵심 수치는 서로 다른 출처 2개로 교차 확인. 값이 엇갈리면 둘 다 적고 차이 이유를 한 줄.
- 못 찾은 항목은 추정으로 채우지 말고 **DATA GAP 박스**로 남긴다.
- **11 출처 추적 뷰의 티어별 개수가 곧 이 리포트의 신뢰도**다. T1·T2 비중을 앞에 노출한다.

### 3. 조사 깊이가 얕으면 레이아웃으로 덮지 않는다

마케터 CH1의 조사 6스텝(카테고리 정의 · 시장 규모 · 공급측 · 수요측 · 이종업계 · 트렌드) 중
빠진 게 있으면, 예쁜 뷰로 채우지 말고 **00 요약 뷰 상단에 "이번 조사에서 빠진 것"을 먼저 적는다.**
특히 **수요측(소비자 리뷰·커뮤니티 원문) 조사가 없으면 04 포지셔닝 맵의 축은 신뢰할 수 없다** —
그 사실을 04 뷰에 명시한다.

## 디자인 토큰 — 모노톤 + 포인트 4색 고정

```css
:root{
  /* 기본 = 모노톤. 아래 4색 외에는 절대 새 색을 만들지 않는다 */
  --bg:#ffffff; --panel:#fff; --panel2:#fafafa; --ink:#161616; --muted:#77756e; --line:#e6e5e3;
  --accent:#1a1a17; --accent2:#ececea; --shadow:0 12px 30px rgba(24,24,24,.06);
  /* 포인트 4색(고정) — 분류·강조가 꼭 필요한 곳에만 */
  --pink:#ff86f6; --blue:#2e53f9; --lime:#c5ff79; --orange:#ff6e23;
  --pink2:#ffeafd; --blue2:#e7ecfe; --lime2:#eeffd9; --orange2:#ffe4d3;
}
```

**의미 배정 (출처 신뢰도 티어) — 항상 이 순서로:**
- `--blue` = T1 · 공식·1차 출처(IR·공식 발표·서비스 문서) · 핵심 정보
- `--lime` = T2 · 산업·연구 기관 자료 · 긍정·기회
- `--pink` = T3 · 검증된 업계 매체·인터뷰 · 보류·중간 위험
- `--orange` = T4 · 탐색용 자료(블로그·커뮤니티) · 위험·회피, 가설 발견용으로만

사용 룰: 새 색 생성 금지. 의미 없는 장식으로 쓰지 않는다 — 분류·강조가 꼭 필요할 때만.
출처 없는 항목은 "추정"으로 표기하고 색을 매기지 않는다.

**바탕은 화이트다.** `--bg`와 `--panel`이 둘 다 `#fff`라서 카드가 바탕에 묻힐 수 있다.
위계는 색이 아니라 아래 세 가지로 만든다 — 이걸 어기면 화면이 납작해진다.

1. 모든 표면(card·flow-step·source-card 등)에 `1px solid var(--line)`을 남긴다
2. **중첩 카드**(카드 안의 카드)만 `#fafafa`로 한 단계 내린다. 3단 중첩은 다시 `#fff`
3. 표의 그룹 헤더행·합계행은 `tr.grouprow` / `tr.sumrow`로 톤을 준다

회색 바탕으로 되돌리지 않는다. 과거 버전의 웜그레이(#f2f1ee·#f9f8f4·#f6f4ee 계열)는
전부 폐기됐다 — 새로 만들 때 그 값을 다시 쓰면 안 된다.

## 레이아웃 — 사이드바 + 뷰 전환

```
┌──────────────────────────────────────────────┐
│ 다크 topbar (프로젝트명 + 핵심 지표)             │
├───────────┬────────────────────────────────────┤
│ 사이드바    │ 현재 활성 뷰 (00~11 중 1개만 표시)     │
│ · 프로젝트  │  page-head(eyebrow+title+meta)     │
│   미니카드  │  grid cols / card / table 등        │
│ · nav-item │                                     │
│   00~11    │                                     │
└───────────┴────────────────────────────────────┘
```

- 사이드바 nav-item 클릭 → JS로 `.view.active` 토글, 다른 뷰는 `display:none`
- 각 뷰는 독립된 `<section class="view" id="...">` — 스크롤 위치가 아니라 **전체 교체**
- 모바일(≤740px)에서는 사이드바가 상단 가로 스크롤 칩으로 축소

핵심 컴포넌트: `.card` `.card.metric`(큰 숫자) `.decision`(다크 결론 히어로) `.flow`(파이프라인 단계)
`.table-wrap table.table`(출처·데이터 표) `.tag`(포인트 4색 분류 태그) `.tl`(일자별 타임라인)

## 표 규칙 (가장 자주 깨지는 곳)

**클래스 이름은 `table`이다.** `class="t"`로 쓰면 CSS가 하나도 안 걸려서
border-collapse·패딩·헤더 스타일·min-width가 전부 빠진 맨몸 표가 나온다.
겉보기엔 "레이아웃이 깨졌다"로 보이지만 원인은 이 한 글자다.

```html
<div class="table-wrap"><table class="table table--md"> … </table></div>
```

`.table` 기본 `min-width:1020px`은 **6열 이상 기준**이다. 열이 적으면 모디파이어를 붙인다.
안 붙이면 좁은 폭에서 셀이 30px까지 눌려 한 글자씩 줄바꿈된다.

| 열 수 | 클래스 |
|---|---|
| 3열 이하 | `table table--sm` (560px) |
| 4열 | `table table--md` (720px) |
| 5열 | `table table--lg` (880px) |
| 6열 이상 | `table` (1020px 기본값) |

그 외:
- 숫자 열은 `<td class="num">` — 우측 정렬 + `tabular-nums` + 줄바꿈 금지. 헤더도 `<th class="num">`
- **rowspan으로 구분 열을 묶지 않는다.** 남은 열의 폭을 잡아먹는다.
  전폭 그룹 헤더행 `<tr class="grouprow"><td colspan="N">구분명</td></tr>`을 쓴다
- 합계행은 `<tr class="sumrow">`

### 일정은 표로 만들지 않는다 — `.tl`을 쓴다

날짜 축이 있는 일정을 6열 표로 짜면 어느 폭에서도 읽히지 않는다.
좌측 날짜 레일 + 우측 트랙 N개 구조인 `.tl`을 쓴다. 640px 이하에서 세로로 접힌다.

```html
<div class="tl">
  <div class="tl-row today">                     <!-- .off = 휴무행 -->
    <div class="tl-date"><b>8/21 금</b><span>D-10</span></div>
    <div class="tl-body">
      <div class="tl-track"><em>전략·기획</em><p>…</p></div>
      <div class="tl-track"><em>크리에이티브</em><p>…</p></div>
      <div class="tl-gate"><em>게이트</em><span class="tag red">전략 락</span></div>
    </div>
  </div>
</div>
```

**휴무일을 일정에서 빼고 센다.** 주말·공휴일을 작업일로 잡으면 계획 자체가 거짓말이 된다.
`.tl-row.off`로 남겨서 "여기는 안 쓴다"를 보이게 한다.

## 유연 레이아웃 규칙 (모바일에서 깨지지 않게 — 필수)

1. 절대좌표 금지. 카드 그리드는 `grid-template-columns: repeat(auto-fit, minmax(...,1fr))`.
2. 표·차트는 `overflow-x: auto` 컨테이너 안에 — 페이지 가로 스크롤 금지.
3. 숫자는 항상 `font-variant-numeric: tabular-nums`.
4. 사이드바는 데스크톱 고정폭(약 240~280px), 모바일은 가로 스크롤 칩으로 전환.
5. `.grid > *`와 `.card`에 `min-width:0`. 안 주면 카드 안의 표가 카드를 밀어
   페이지 전체가 가로로 흐른다.
6. 만든 뒤 **1440 / 1100 / 900 / 740 / 620 / 430px 여섯 폭에서 확인**한다.
   확인 항목 두 개 — 페이지 가로 스크롤이 생기는가, 표 셀이 50px 아래로 눌리는가.

## 제안·기획 건이면 심리 렌즈 산출물이 들어갈 자리가 있다

마케터 P0(제안 심리 게이트)를 통과한 산출물은 아래 뷰에 **각각 착지시킨다.**
따로 모아 부록으로 두지 않는다 — 부록에 두면 부록으로 읽힌다. 근거는 `.claude/library/proposal-psychology.md`.

| 렌즈 | 착지 뷰 | 형태 |
|---|---|---|
| ① 손실 회피 | **01 브리프·문제 정의** | 재정의 박스 아래 "안 했을 때 잃는 것" 3항목 카드 |
| ② 문제 재정의 | **01 브리프·문제 정의** | `.request-vs` — 좌 CLIENT REQUEST / 우 REFRAMED PROBLEM |
| ③ 내부 보고 | **10 추천 전략** 말미 | 임원 반대 질문 3 + 답, 보고용 명분 한 줄 표 |
| ④ 서사 | **09 전략 대안** | 각 안에 "왜 이 방향을 생각했는가" 한 줄 + **버린 안과 이유** |
| 종합 | **00 요약** | "우리만 쓸 수 있는 문장" 목록. 0개면 이 대시보드는 아직 완성이 아니다 |

경쟁 제안 예측이 필요한 건(입찰·경쟁 PT)이면 **10과 11 사이에 뷰를 하나 더 넣는다** —
경쟁사 표준 제안 예측표 + 우리 +α 목록(각각 남들이 못 쓰는 이유·비용·꽂히는 평가 항목).

## 흔한 실수

- **표에 `class="t"`를 씀** → CSS가 안 걸려 맨몸 표가 나온다. `class="table"`이다.
- **열이 적은 표에 모디파이어를 안 붙임** → 좁은 폭에서 셀이 눌린다.
- **바탕을 회색으로 되돌림** → 화이트가 표준이다. 위계는 보더와 중첩 카드로 만든다.
- **일정을 6열 표로 만듦** → `.tl` 블록을 쓴다.
- **주말을 작업일에 포함해서 일정을 셈** → 실제 가용 일수를 먼저 계산하고 시작한다.

- 스크롤형(list-deck-design)이나 슬라이드형(mx-deck-design)과 헷갈려서 좌측을 목차로 씀 → 여긴 진짜 탭(뷰 전환)이어야 한다.
- 00 요약 또는 11 출처 추적을 생략함 → 이 둘은 항상 있어야 한다.
- 포인트 4색 외에 새 색을 씀 → 절대 금지, 모노톤+4색만.
- 출처 티어(T1~T4) 표기 없이 수치만 씀 → 모든 수치·주장에 티어 + 출처 필수.
- CH1(현황 조사)에서 이미 판단이 섞임 → 판단은 CH2(04·05·07뷰)부터.
