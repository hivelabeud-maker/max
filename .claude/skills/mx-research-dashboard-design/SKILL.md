# MX Research Dashboard Design — 마케터 산출 표준 시스템 (탭형)

`mx-deck-design`(슬라이드 덱)의 짝 스킬. **덱은 위→아래 스크롤, 대시보드는 좌측 탭 클릭으로 뷰 전환.**
좌측 사이드바(nav) + 12뷰 탐색형 구조의 리서치·전략 대시보드 HTML을 만드는 시각 시스템.
**목표: 마케터가 뭘 조사하든 항상 같은 12뷰 구조로 나오게.**

## 이름으로 구분하기

| 스킬 | 좌측 구조 | 상호작용 |
|---|---|---|
| `mx-deck-design` | 없음(슬라이드가 순서대로) | 위→아래 스크롤 |
| `list-deck-design` | 앵커 목차(220px) | 클릭 시 그 섹션으로 스크롤 이동 |
| **`mx-research-dashboard-design`** (이 스킬) | **nav-item 12개 탭** | **클릭 시 뷰가 통째로 전환(다른 뷰는 숨김)** |

## 언제 쓰나

- 마케터 에이전트가 "리서치 쭉 돌려줘" / "마케터 돌려" 결과를 문서로 낼 때 (자동 적용)
- 브랜드 현황 조사 → 진단 → 문제 정의 → 발산까지의 전체 흐름을 한 파일로 추적하고 싶을 때
- 리더 승인·팀 검토용으로 "결론 먼저, 근거는 필요할 때 펼쳐 보기" 형태가 필요할 때

쓰지 말 것: 발표용 슬라이드 덱(그건 `mx-deck-design`), 에디토리얼 리포트(그건 `list-deck-design`).

## 구조 — 12뷰 (마케터 4챕터 → 1:1 매핑)

| 뷰 | 내용 | 마케터 챕터 |
|---|---|---|
| 00 요약 대시보드 | 결론 먼저 + 진행 파이프라인 + 핵심 지표 4칸 | 종합 |
| 01 브리프·문제 정의 | 요청(client request) → 진짜 결정 문제로 재정의 | 0 RFP · CH3 |
| 02 브랜드 팩트북 | 대상 브랜드 사전 이해 | CH1 |
| 03 경쟁 리서치 | 경쟁 브랜드 표 + 출처 (보통 30개 기준) | CH1 |
| 04 포지셔닝 맵 | 축·좌표 근거, XY 포지셔닝 | CH2 |
| 05 화이트스페이스 | 빈자리 기회/함정 판정 | CH2 |
| 06 이종업계 | 타 업계 차용 사례 (보통 30개 기준) | CH1 |
| 07 핵심 인사이트 | 패턴·긴장·So What | CH2→CH3 |
| 08 브랜드 밸류 키워드 | 가치 키워드 도출 | CH3 |
| 09 전략 대안 | 방향 후보 비교·점수 (보통 3안) | CH4 |
| 10 추천 전략 | 추천안 + 실행 원칙 + 하지 않을 것 | CH4 |
| 11 출처·근거 추적 | 전체 출처 티어(T1~T4) 분류 | 전 챕터 |

**00 요약과 11 출처 추적은 절대 생략하지 않는다.** 나머지는 프로젝트 성격에 맞게 가감 가능
(예: RFP가 없으면 01 브리프를 축소, 이종업계 조사가 없으면 06 생략).

## 디자인 토큰 — 모노톤 + 포인트 4색 고정

```css
:root{
  /* 기본 = 모노톤. 아래 4색 외에는 절대 새 색을 만들지 않는다 */
  --bg:#f2f1ee; --panel:#fff; --panel2:#faf9f6; --ink:#161616; --muted:#77756e; --line:#e3e1da;
  --accent:#1a1a17; --accent2:#e6e4dd; --shadow:0 12px 30px rgba(24,24,24,.06);
  /* 포인트 4색(고정) — 분류·강조가 꼭 필요한 곳에만 */
  --pink:#ff86f6; --blue:#2e53f9; --lime:#c5ff79; --orange:#ff6e23;
  --pink2:#ffeafd; --blue2:#e7ecfe; --lime2:#eeffd9; --orange2:#ffe4d3;
}
```

**의미 배정 (출처 신뢰도 티어) — 항상 이 순서로:**
- `--blue` = T1 · 공식·1차 출처(IR·공식 발표·서비스 문서) · 핵심 정보
- `--lime` = T2 · 산업·연구 기관 자료 · 긍정·기회
- `--pink` = T3 · 검증된 업계 매체·인터뷰 · 보류·중간 위험
- `--orange` = T4 · 탐색용 자료(블로그·커뮤니티) · 위험·회피, 가설 발견용으로만

사용 룰: 새 색 생성 금지. 의미 없는 장식으로 쓰지 않는다 — 분류·강조가 꼭 필요할 때만.
출처 없는 항목은 "추정"으로 표기하고 색을 매기지 않는다.

## 레이아웃 — 사이드바 + 뷰 전환

```
┌──────────────────────────────────────────────┐
│ 다크 topbar (프로젝트명 + 핵심 지표)             │
├───────────┬────────────────────────────────────┤
│ 사이드바    │ 현재 활성 뷰 (00~11 중 1개만 표시)     │
│ · 프로젝트  │  page-head(eyebrow+title+meta)     │
│   미니카드  │  grid cols / card / table 등        │
│ · nav-item │                                     │
│   00~11    │                                     │
└───────────┴────────────────────────────────────┘
```

- 사이드바 nav-item 클릭 → JS로 `.view.active` 토글, 다른 뷰는 `display:none`
- 각 뷰는 독립된 `<section class="view" id="...">` — 스크롤 위치가 아니라 **전체 교체**
- 모바일(≤740px)에서는 사이드바가 상단 가로 스크롤 칩으로 축소

핵심 컴포넌트: `.card` `.card.metric`(큰 숫자) `.decision`(다크 결론 히어로) `.flow`(파이프라인 단계)
`.table-wrap table.t`(출처·데이터 표) `.tag`(포인트 4색 분류 태그)

## 유연 레이아웃 규칙 (모바일에서 깨지지 않게 — 필수)

1. 절대좌표 금지. 카드 그리드는 `grid-template-columns: repeat(auto-fit, minmax(...,1fr))`.
2. 표·차트는 `overflow-x: auto` 컨테이너 안에 — 페이지 가로 스크롤 금지.
3. 숫자는 항상 `font-variant-numeric: tabular-nums`.
4. 사이드바는 데스크톱 고정폭(약 240~280px), 모바일은 가로 스크롤 칩으로 전환.

## 빠른 시작

```bash
cp .claude/skills/research-dashboard-design/template.html ./<프로젝트명>-research.html
# 사이드바 nav-item 12개 + 각 view 섹션의 텍스트·데이터만 치환. 색·구조는 손대지 않는다.
```

## 흔한 실수

- 스크롤형(list-deck-design)이나 슬라이드형(mx-deck-design)과 헷갈려서 좌측을 목차로 씀 → 여긴 진짜 탭(뷰 전환)이어야 한다.
- 00 요약 또는 11 출처 추적을 생략함 → 이 둘은 항상 있어야 한다.
- 포인트 4색 외에 새 색을 씀 → 절대 금지, 모노톤+4색만.
- 출처 티어(T1~T4) 표기 없이 수치만 씀 → 모든 수치·주장에 티어 + 출처 필수.
- CH1(현황 조사)에서 이미 판단이 섞임 → 판단은 CH2(04·05·07뷰)부터.
