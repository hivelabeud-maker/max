# 부분 수정과 연속성 잠금 규칙 (Gate 5)

## 먼저 작업을 분류한다

프롬프트를 쓰기 전에 현재 작업을 아래 6개 중 하나로 먼저 분류한다. 분류 없이 바로 프롬프트를 쓰지 않는다.

- 신규 생성
- 카메라 파생
- 국부 수정
- 톤 변경
- FX 추가
- 업스케일

## 한 패스에 하나만

분류한 그 한 가지만 진행한다. 두 가지를 한 프롬프트에 합치지 않는다. 구조 변경, 카메라 변경, 시간대 변경, 캐릭터 합성, FX 추가, 업스케일을 동시에 수행하지 않는다. 여러 작업이 필요하면 순서를 정해 하나씩 요청한다.

## 카메라를 파생할 때

승인된 구조 마스터에서 카메라만 바꿀 때는 성의 실루엣, 문양, 재질, 지형, 시간대, 날씨와 주광 방향을 그대로 유지한다.

## 클린 배경 플레이트를 먼저 승인받는다

인물과 FX가 들어가기 전, 캐릭터가 합성될 공간이 확보된 클린 배경 플레이트를 먼저 승인받는다. 클린 플레이트가 승인되지 않은 상태에서 캐릭터·FX 합성으로 넘어가지 않는다.

## 편집 시 먼저 잠그는 항목

기존 이미지를 고칠 때는 `06-master-lock.md`에서 확정한 요소부터 다시 확인하고, 아래 4가지를 이번 편집 프롬프트에 명시한다.

| 영역 | 정의 |
|---|---|
| 유지 영역 | 픽셀 단위로 보존할 부분 |
| 수정 영역 | 이번 패스에서 바꿀 정확한 범위 |
| 보호 영역 | 인접하지만 절대 건드리면 안 되는 부분(수정 영역과 붙어 있어 침범 위험이 있는 곳) |
| 추가 금지 항목 | 이번 편집에서 새로 생기면 안 되는 요소 목록 |

## 개폐 상태가 있는 구조물(문, 게이트, 커튼 등)을 다룰 때

- 닫힌 상태에는 내부 빛, 틈새 발광, 바닥 투사광, 개방 동작의 흔적을 만들지 않는다.
- 개방은 반드시 별도 프레임에서 다룬다. 내부 깊이·후면 공간이 먼저 보이고, 그 다음에 내부 광원을 활성화한다.
- 시간대와 외부 하늘은 개폐 상태와 무관하게 유지한다.

## 검증 질문

프롬프트를 보내기 전에 스스로 확인한다.

- 이번 패스가 정확히 몇 가지 변화를 요구하는가? 2개 이상이면 쪼갠다.
- 유지 영역을 문장으로 명시했는가, 아니면 "그대로 유지"라고만 뭉뚱그렸는가? 뭉뚱그렸다면 픽셀 단위 기준(카메라·축·비율·시간대·재질)을 구체적으로 나열한다.
- 이 수정이 `06-master-lock.md`의 잠금 항목을 건드리는가? 건드린다면 즉흥적으로 진행하지 말고 `16-revision-protocol.md`를 먼저 확인한다.
