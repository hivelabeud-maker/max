# 승인 게이트 상세 — 이 파일이 게이트 정의의 유일한 정본이다

다른 문서(SKILL.md, Claude Project Instructions 등)는 게이트 순서를 여기서 참조만 하고 재서술하지 않는다. 게이트 규칙을 바꿀 때는 이 파일 하나만 고친다.

**6단계 승인 게이트를 반드시 순서대로 진행한다. 사용자가 현재 단계를 승인하기 전에는 다음 단계로 넘어가지 않는다.**

## Gate 1 — SB 분석

원본 SB 전체를 먼저 분석한다. 장면별 표로 정리한다. 세부 컬럼은 `01-sb-analysis.md` 참조. 분석이 끝나면 전체 SB의 공간 이동 경로와 감정 곡선을 요약한다.

금지: 이미지 프롬프트.

## Gate 2 — Visual Bible

Gate 1이 승인된 후 전체 영상에 적용할 Visual Bible을 작성한다. 세부 항목은 `03-visual-bible.md` 참조. 시간대는 구조 마스터용과 서사용을 구분하며 세부는 `10-time-of-day.md` 참조.

금지: 이미지 프롬프트.

## Gate 3 — Shot Matrix

Visual Bible이 승인되면 각 장면의 Shot Matrix를 작성한다. 세부 컬럼은 `04-shot-matrix.md` 참조. 실제 영상의 순서와 이미지 제작 순서를 구분한다 — 같은 파일에 두 순서를 모두 명시한다.

## Gate 4 — 구조 마스터 제작

공간마다 하나의 구조 마스터를 확정한다. 세 단계로 진행하며, 각 단계도 사용자 승인 없이 다음으로 넘어가지 않는다.

1. **마스터 시안 3안 비교** — 동일 세계관·동일 장소를 해석 강도만 다르게 A(SB 충실형) / B(AION 환경 확장형) / C(시네마틱 스케일 극대화형) 3안으로 만들어 비교한다. 세부는 `05-master-concept-set.md` 참조. 여기서 처음 이미지 프롬프트를 쓴다.
2. **Structure Master 잠금** — 3안 중 하나가 승인되면 그 이미지를 구조 마스터로 잠근다. 세부는 `06-master-lock.md` 참조.
3. **Scene Gap Analysis** — 마스터 잠금 직후, SB만으로 부족한 공백을 분석한다. 세부는 `07-scene-gap-analysis.md` 참조. 이 단계에서는 추가 씬의 목적과 목록만 승인받고 장문 프롬프트는 아직 쓰지 않는다.

레퍼런스 역할 분류는 `02-reference-role-audit.md`, 프롬프트 작성 순서와 고정 문장은 `08-prompt-formula.md`, 신규 생성 vs 파생 편집의 도구 선택은 `11-tool-routing.md`를 따른다.

## Gate 5 — 파생과 부분 수정

Gate 4에서 확정된 구조 마스터와 Scene Gap Analysis 목록을 바탕으로 실제 산출물을 만든다. 한 번의 생성에서는 하나의 변수만 바꾼다. 분류와 규칙은 `09-continuity-lock-and-local-edit.md` 참조. 인물·FX가 들어가기 전, 캐릭터가 합성될 공간이 확보된 클린 배경 플레이트를 먼저 승인받는다.

## Gate 6 — 최종 출력

구조·카메라·톤이 모두 승인된 후에만 업스케일과 영상화를 진행한다. 도구 설정은 `11-tool-routing.md`, 관찰 가능한 품질 조건은 `12-qc-checklist.md` 참조.

## 모든 게이트 공통 규칙

- 매 응답 시작 시 현재 진행 중인 Gate 번호와 작업 목적을 표시한다.
- 각 게이트 제출은 표와 판단 근거를 먼저 제시하고, `승인할 항목 / 수정 가능한 항목 / 다음 Gate에서 할 일`로 끝낸다.
- Gate 1, 2에서는 이미지 프롬프트를 작성하지 않는다. Gate 4 이후에만 복사 가능한 한국어 이미지 프롬프트를 제공한다.
- 각 프롬프트 끝에는 사용할 모델, 이미지 비율, 권장 해상도, 레퍼런스 역할, 수정 범위, 검수 항목을 표시한다.
- 기존 이미지의 구조를 유지해야 하는 작업에서는 항상 아래 문장을 프롬프트 맨 앞에 그대로 적용한다.

> "현재 승인된 이미지를 유일한 구조 기준으로 사용한다. 전체 실루엣, 중앙축, 높이와 폭의 비례, 문과 계단의 위치, 좌우 건축 배치, 지형, 시간대, 날씨, 색상 팔레트와 주광 방향을 변경하지 않는다. 이번 패스에서는 지정된 편집 변수 하나만 변경한다."

- 사용자의 명시적 승인 없이 다음 게이트로 진행하지 않는다.
- 부분승인·반려가 발생하면 `16-revision-protocol.md`를 따른다.

## 왜 Gate 4에 세 단계가 묶여 있는가

3안 비교·마스터 잠금·Scene Gap Analysis는 서로 다른 판단(비교/확정/공백분석)이라 별도 파일로 분리했다. 다만 세 절차 모두 "아직 파생 제작을 시작하지 않은, 구조 마스터를 확정하는 단계"라는 공통점이 있어 하나의 승인 게이트 번호 아래 하위 단계로 묶었다 — 파일은 섞지 않되 게이트 번호는 사용자가 실제 부르는 6단계 체계를 따른다.
