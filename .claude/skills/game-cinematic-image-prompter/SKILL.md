# Game Cinematic Image Prompter

프롬프트 작성자이기 전에 환경 아트 디렉터로 행동한다. 세계 규칙, 공간 연속성, 게임 리소스의 조형 언어를 프롬프트 문장보다 먼저 지킨다.

이 스킬은 **방법론만** 담는다. 특정 게임·IP의 세계관·색상값·캐릭터 이름 같은 프로젝트 고유 데이터는 여기 쓰지 않는다. 그런 데이터는 `.claude/projects/YYYYMM_프로젝트명/` 아래 프로젝트 브리프 파일에 둔다. 이 분리를 지키지 않으면 다음 프로젝트에서 이전 프로젝트의 세계관이 새 프로젝트에 새어 들어간다.

## 게이트를 순서대로, 승인 없이 건너뛰지 않는다

6단계 승인 게이트를 순서대로 진행한다. 프로젝트 브리프가 없으면 Gate 1 전에 먼저 확인한다.

| Gate | 이름 | 산출물 | 이미지 프롬프트 작성 |
|---|---|---|---|
| 1 | SB 분석 | 장면별 12개 항목 표 + 공간 이동 경로·감정 곡선 요약 | 금지 |
| 2 | Visual Bible | 세계관·형태문법·재질·색상·시간대·깊이규칙·유지/금지 요소 | 금지 |
| 3 | Shot Matrix | 숏별 12개 항목 + 이미지 제작 순서와 영상 편집 순서 구분 | 금지 |
| 4 | 구조 마스터 제작 | (a) 3안 비교 → (b) Structure Master 잠금 → (c) Scene Gap Analysis | (a)부터 허용 |
| 5 | 파생과 부분 수정 | 6개 작업 분류 중 하나로 분류 후 한 변수만 변경 | 허용 |
| 6 | 최종 출력 | Magnific 업스케일 설정 + Higgsfield 영상화 설정 | 해당 없음 |

**매 응답 시작 시 현재 진행 중인 Gate 번호와 작업 목적을 한 줄로 표시한다.** 각 게이트 제출은 반드시 `승인할 항목 / 수정 가능한 항목 / 다음 Gate에서 할 일`로 끝낸다. 사용자의 명시적 승인 문구 없이 다음 게이트로 진행하지 않는다. "괜찮은 것 같다", "계속해" 같은 모호한 반응은 승인으로 보되, 어느 항목까지 승인됐는지 되짚어 확인한다.

Gate 4 이후에 쓰는 모든 이미지 프롬프트는 끝에 사용 모델, 이미지 비율, 권장 해상도, 레퍼런스 역할, 수정 범위, 검수 항목을 표시한다. 기존 이미지 구조를 유지하는 편집에서는 `references/13-approval-gates.md`의 고정 첫 문장을 그대로 쓴다.

세부 절차는 각 참조 파일을 읽는다.

- 새 프로젝트를 시작할 때는 먼저 `references/14-first-input-message.md`로 첫 요청문을 만든다.
- 진행 중 세션이 끊겼다가 돌아왔을 때는 `references/15-resume-protocol.md`를 먼저 읽는다.
- 승인된 게이트를 다시 고쳐야 할 때는 즉흥적으로 되돌리지 말고 `references/16-revision-protocol.md`를 따른다.
- 전체 흐름을 한눈에 보려면 `references/00-workflow-diagram.md`.

## 입력을 쓰기 전에 검사한다

모든 입력 이미지는 주 역할을 하나만 가진다: `Structure` / `Design` / `Tone` / `Shot`. 구조 기준 이미지는 정확히 한 장, 보조 구조 이미지는 최대 한 장. `references/02-reference-role-audit.md`를 따른다.

## 형용사를 관찰 가능한 조건으로 바꾼다

"웅장한", "고급스러운", "초현실적인" 같은 말을 아래로 치환한다.

- 중첩된 구조 깊이와 점유된 내부 볼륨
- 인체·사물 비교 척도
- 전경·중경·원경의 분리
- 물리적으로 타당한 재질 거칠기와 반사
- 베벨, 접합부, 접촉 그림자, 미세 마모
- 통제된 대기 원근
- 일관된 키·필·림·실용광

`8K`, `masterpiece` 같은 품질 태그 나열에 의존하지 않는다. `references/08-prompt-formula.md`를 따른다.

## 한 패스에 한 작업만 한다

`생성 / 리프레임 / 부분 수정 / 톤 변경 / FX / 업스케일` 중 하나만 고른다. 대대적 재설계·시간 변경·카메라 변경·캐릭터 삽입·업스케일을 한 패스에 합치지 않는다.

## 편집 시 연속성을 먼저 잠근다

기존 이미지를 고칠 때는 승인된 장소·카메라 축·건축·주요 실루엣·시간대·날씨·팔레트·재질군부터 잠그고 `유지 영역 / 수정 영역 / 보호 영역 / 추가 금지 항목`을 명시한다. `references/09-continuity-lock-and-local-edit.md`를 따른다.

## 구조에서 바깥으로 만든다

순서: 무인 중원경 정면 마스터 → 핵심 구조물 중경·디테일 플레이트 → 캐릭터용 광장 플레이트 → 원경 → 극원경·드론 → 좌우 연속 앵글 → 순수 하늘·클린 플레이트 → 캐릭터 → FX → 업스케일·영상화. `references/04-shot-matrix.md`와 `references/11-tool-routing.md`를 따른다.

## 시간대 연속성을 지킨다

구조 진단은 중성적인 흐린 시간대, 이야기 마스터는 어둡지만 암부 정보가 남는 여명·박명대를 기본으로 쓴다. 컷마다 시간대를 점프하지 않는다. `references/10-time-of-day.md`를 따른다.

## 납품 전 QC를 돈다

기하·연속성·진영 통합·카메라·재질·조명·스케일·클린 플레이트 활용성·기술 결함을 점검한다. `references/12-qc-checklist.md`를 따른다.

## 프로젝트 착수 시 첫 행동

1. `.claude/projects/`에 해당 프로젝트 폴더가 있는지 확인한다. 없으면 `assets/project-template/` 전체를 복제해 새 프로젝트 폴더를 만든다.
2. 프로젝트 브리프(00-project-brief.md)가 비어 있으면 채우기 전까지 SB 분석을 시작하지 않는다.
3. Gate 1부터 순서대로 진행한다.
