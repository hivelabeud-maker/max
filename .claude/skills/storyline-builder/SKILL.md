# 스토리라인 빌더

`pyramid-principle`로 지배 메시지와 키라인을 확정한 다음, 그것을 장표 순서로 펴는 단계다.
결과를 `mx-deck-design`(발표용) 또는 `mx-research-dashboard-design`(리서치 산출)에 넘긴다.

규칙 하나: **한 줄이 한 장이고, 그 줄이 그대로 슬라이드 제목이 된다.**

## 제목 쓰는 법
제목은 발견을 문장으로 쓴다.
- ✗ "시장 분석" → ✓ "시장은 40% 컸는데 우리 매출은 5% 줄었다"
- ✗ "타깃 정의" → ✓ "구매를 결정하는 건 30대가 아니라 그 옆의 20대다"
- ✗ "제작 방향" → ✓ "첫 3초에 제품이 뭔지 보이면 이탈이 절반으로 준다"

제목만 순서대로 읽었을 때 읽는 사람이 결론까지 도달해야 한다. 도달하지 못하면 줄이 빠졌거나 순서가 틀렸다.

## 서사 형태 고르기

| 상황 | 흐름 |
|---|---|
| 경쟁 입찰 제안 | 상황 → 문제(진짜 문제) → 관점 한 문장 → 전략 → 실행안 → 일정·견적 |
| 리브랜딩·BX | 지금 브랜드가 받는 오해 → 그 오해의 원인 → 우리가 잡을 관점 → 시스템 → 적용 |
| 캠페인·UA | 타깃의 하루 → 지금 소재가 실패하는 지점 → 바꿀 축 → 소재안 → 측정 |
| 리서치 보고 | 결론 → 근거 3~4 → 반대 가능성 → 다음 결정 |
| 임원 보고 | 결론 → 필요한 의사결정 → 근거 → 리스크 |

SCR(Situation-Complication-Resolution)이 기본형이다. 상황은 상대가 이미 아는 사실로 열고, 문제는 상대가 몰랐던 사실로 치고, 해결은 우리만 낼 수 있는 것으로 닫는다.

## 절차
1. `pyramid-principle` 산출(지배 메시지 + 키라인)을 가져온다. 없으면 먼저 돌린다
2. 서사 형태를 고른다
3. 키라인 하나당 3~6줄로 편다. 각 줄이 슬라이드 제목이다
4. 줄마다 담을 것을 적는다 — 차트/맵/시안/표 중 무엇인지
5. 제목만 이어 읽는 테스트를 한다
6. 장수를 확인한다. 30분 발표는 25~35장, 15분은 12~18장

## 출력 템플릿

```markdown
## 스토리라인
| # | 슬라이드 제목(= 메시지) | 챕터 | 담을 것 | 근거·출처 |
|---|---|---|---|---|
| 1 |  | 상황 | 사진 1컷 | — |
| 2 |  | 상황 | 시장 규모 차트 | T1 |

## 제목 이어 읽기 테스트
{1번부터 마지막까지 제목만 붙여 쓴 문단}
→ 결론에 도달하는가: 예 / 아니오(끊기는 지점: N번)

## 장수
총 N장 / 발표 M분 / 장당 평균 X초
```

## 품질 게이트
- 주제 라벨로 남은 제목이 있는가
- 근거 없이 주장만 있는 장이 연속 3장 이상인가
- 상대가 이미 아는 얘기가 앞에 5장 넘게 깔려 있는가
- 관점 한 문장(`concept-director` 산출)이 덱 안에 명시적으로 있는가
