# 제안 고도화 파이프라인

리서치가 제안의 명분이 되기까지 거치는 순서. 스킬 7종이 이 순서대로 물린다.

```
0. RFP 분석          rfp-analyst          → 명시·숨은·미정의·위험 4분류
1. 문제 구조화        mece-issue-tree      → 이슈트리 + 가설 + 반증 테스트
2. 관점 고정          concept-director     → 관점 한 문장 (이후 전 매체 상속)
3. 조사              marketer CH1 (S1~S6) → 팩트북
4. 근거 검증          source-grading       → A~F × 1~6 등급, 독립성 4시험, T1~T4
5. 인사이트           insight-derivation   → 사실→관찰→긴장→인사이트→함의 + UX 5질문
6. 문서 논리          pyramid-principle    → 지배 메시지 + 키라인 + 근거
7. 장표 순서          storyline-builder    → 한 줄 = 한 장, 제목은 발견
8. 조판              mx-deck-design / mx-research-dashboard-design
9. 검수              critic → review-panel → objection-library → fact-checker → delivery-gate
```

브리프가 필요한 프로젝트(외주 발주·시안 착수)는 2번 다음에 `creative-brief`를 끼운다.

---

## 어떻게 지시해야 이 관점까지 나오나

에이전트는 요청 문장에 걸린 트리거로 스킬을 부른다. **"시장조사 해줘"만 던지면 3번에서 멈춘다.** 팩트는 쌓이는데 인사이트와 명분이 안 나오는 이유가 이거다.

지시할 때 아래 네 가지를 문장에 넣으면 4~7번까지 자동으로 물린다.

### 1) 결정 질문을 준다
조사 주제가 아니라 **답해야 할 질문**을 준다.
- ✗ "정수기 시장 조사해줘"
- ✓ "20대에게 이 브랜드가 안 팔리는 이유가 인지도인지 이해도인지 판정해줘"

질문이 있으면 `mece-issue-tree`가 걸리고, 조사 축이 질문에서 나온다.

### 2) 관점을 먼저 고정하라고 말한다
- ✓ "조사 전에 관점 한 문장부터 잡고 시작해줘"

`concept-director`가 먼저 돌면 이후 모든 조사·인사이트가 그 관점에 물려 정렬된다. 이 단계를 건너뛰면 사실은 많고 이야기는 없는 리서치가 나온다.

### 3) UX·행동 관점을 명시한다
- ✓ "사용자 여정 어느 단계에서 막히는지까지 보고, 인사이트마다 UX 함의를 붙여줘"

`insight-derivation`의 UX 5질문이 강제로 통과된다: 여정 단계 / 막힌 일 / 없던 정보 / 대체한 것 / 뒤집을 지점.

### 4) 근거 수준을 지정한다
- ✓ "핵심 수치는 독립 출처 2건 교차 확인하고 등급 붙여줘. 못 찾으면 DATA GAP으로 표시"

`source-grading`이 걸리고, T4가 본문에 새는 걸 막는다.

### 한 문장으로 다 넣기

> "{브랜드}가 {누구}에게 {무엇이} 안 되는 이유를 판정하는 게 목적이야. 관점 한 문장부터 잡고, 조사는 축 나눠서 하고, 핵심 수치는 교차 확인해서 등급 달고, 인사이트는 사용자 여정 어디서 막히는지까지 내려가서 제안이랑 연결해줘. 마지막에 결론부터 목차 짜고 덱으로."

이 한 문장이 0→8번을 전부 건다.

---

## 명분이 서 있는지 보는 법

제안서의 모든 주장은 아래 네 줄로 역추적되어야 한다. 하나라도 비면 그 장은 취향이다.

```
근거: {검증된 사실 + 출처 티어}
관찰: {서로 안 맞는 사실 두 개}
판단: {그 긴장의 원인에 대한 인사이트}
그래서: {이 제안이 긴장을 어디서 끊는가}
```

`mx-research-dashboard-design`의 11번 뷰(출처추적)가 이 역추적을 화면으로 보여주는 자리다.

---

## 흔한 실패와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 사실만 많고 "그래서 뭐"가 없다 | 5번을 안 돌렸다 | `insight-derivation` — 충돌하는 사실 쌍부터 찾는다 |
| 제안이 조사와 따로 논다 | 명분 4줄이 안 붙었다 | 인사이트 카드에 "연결되는 제안" 칸을 채운다 |
| 목차가 나열식이다 | 6번을 건너뛰고 조판했다 | `pyramid-principle`로 지배 메시지부터 다시 |
| 슬라이드 제목이 "시장 분석" | 7번을 건너뛰었다 | `storyline-builder` 제목 이어 읽기 테스트 |
| 클라이언트가 숫자를 물고 늘어진다 | 4번이 약하다 | `source-grading` 교차 확인 + `objection-library` |
| 시안 3회차에 방향이 뒤집힌다 | 브리프가 없다 | `creative-brief` 10개 질문 |
