# 제안 행동심리 — 기획자가 자주 빠지는 통념 깨기

> RFP 제안·마케팅 기획 착수 시 **반드시 경유**한다.
> 대상: `rfp-analyst` · `marketer` · `critic` · `review-panel` · 제안서 작성 전 과정.
> 목적: 요구사항을 잘 채운 제안이 아니라 **의사결정자가 승인할 수 있는 제안**을 만든다.

## 왜 이게 따로 필요한가

제안서는 논리로 평가받는 것 같지만 실제로는 사람이 고른다. 심사위원은 회사가 아니라 개인이고,
개인은 자기 자리에서 안전한 선택을 한다. RFP 요구사항만 성실히 채우면 경쟁사 3~5부와
내용의 70%가 겹친다. 상대평가에서 그 70%는 점수를 만들지 않는다.

---

## 1. 손실 회피 — 얻는 이득보다 잃는 공포가 크다

| | |
|---|---|
| **통념** | "우리 안을 쓰면 매출이 30% 오릅니다" |
| **실제** | 담당자는 성공 보상보다 **실패 시 자기가 질 책임**을 훨씬 크게 느낀다 |

**적용**
- 얻는 것만 쓰지 말고 **안 했을 때 계속 새는 비용·기회비용·리스크**를 같이 쓴다
- 우리 안을 고르면 그 리스크가 **어떻게 0이 되는지**를 절차로 증명한다
- 리스크 관리 항목을 부록이 아니라 **본문에** 둔다

**AION2 건 적용 예** — 논란 발생 시 광고 즉시 정지 프로토콜. 대행사에게는 매출 손실이지만,
담당자에게는 "세 번째 논란이 터져도 내가 안 깨진다"는 보험이다. 먼저 제안하면 신뢰를 산다.

---

## 2. 과신·더닝크루거 — 고객사도 자기 문제를 모른다

| | |
|---|---|
| **통념** | "RFP를 썼으니 자기들이 뭘 원하는지 정확히 알 것이다" |
| **실제** | 고객사 스스로 문제의 본질을 **잘못 진단하고 있을 확률이 높다** |

**적용**
- RFP를 수동적으로 수용하지 말고, 상위 사업 목표·포트폴리오 관점에서 **문제를 재정의**한다
- 재정의는 반드시 **RFP 원문 인용 + 외부 근거**로 뒷받침한다. 근거 없는 재정의는 오만으로 읽힌다
- 재정의 문장은 **한 문장**으로. 길면 주장이 아니라 변명이 된다

**함정** — 재정의가 RFP 요구를 부정하면 안 된다. 요구는 다 채우고, 그 위에서 "진짜 문제는 이것"을 얹는다.

---

## 3. 인지적 편안함·자기보존 — 담당자는 내부 보고를 통과해야 한다

| | |
|---|---|
| **통념** | "가장 신선하고 파격적인 안이 뽑힌다" |
| **실제** | 담당자의 진짜 니즈는 **"이걸 들고 들어가면 내가 승인받을 수 있는가"** |

**적용**
- 제안서를 **담당자가 그대로 상신할 수 있는 보고서 완제품**으로 만든다
- 보고용 명분(왜 지금 이걸 해야 하는가)과 프로세스를 **정량**으로 준다
- 임원이 던질 반대 질문을 미리 예상해 제안서 안에서 답을 끝내 둔다
- 아무리 좋은 아이디어도 상사에게 깨질 위험이 보이면 채택되지 않는다

---

## 4. 서사 몰입 — 자랑보다 의도와 과정이 신뢰를 만든다

| | |
|---|---|
| **통념** | "우리 USP와 실적을 나열하면 설득된다" |
| **실제** | 사람은 **결핍이 있는 주체가 의도를 갖고 성과를 내는 과정**에 몰입한다 |

**적용**
- 결과물·스펙만 늘어놓지 말고 **어떤 문제의식에서 이 설계가 나왔는지** 과정을 보인다
- 우리 약점을 숨기지 말고 먼저 말한 뒤 보완 구조를 보인다. 감추면 실사에서 드러난다
- 첫 3분을 회사 소개로 쓰지 않는다. **고객의 현실**로 연다

---

## 착수 전 자문 7문

1. 이 제안을 **안 고르면** 고객이 잃는 것을 한 문장으로 쓸 수 있는가
2. RFP가 말하지 않은 **진짜 문제**를 근거와 함께 재정의했는가
3. 담당자가 이걸 그대로 **상신**할 수 있는가
4. 임원의 **반대 질문 3개**에 제안서 안에서 답이 끝나는가
5. 경쟁사도 쓸 문장을 빼면 **우리만 쓸 수 있는 문장**이 몇 개 남는가
6. 우리 약점을 **먼저** 말했는가
7. 제안서에 쓴 약속 중 **12개월 무상 의무**가 되는 문장이 있는가 (제안 내용은 계약과 동일 효력인 경우가 많다)

## 프롬프트 3종

### P1 · 손실 회피 보강
```
우리가 강조하는 핵심 가치는 [제안 내용]이다. 고객사가 이 제안을 채택하지 않고
기존 방식을 고수했을 때 발생할 '눈에 보이지 않는 손실'(기회비용·효율 저하·비용 유출)을
행동경제학 관점에서 3가지로 분석해줘. 그리고 우리 제안이 그 리스크를 어떻게
방지하는지 절차로 써줘.
```

### P2 · 내부 보고 통과
```
내가 [고객사 산업군]의 [담당자 직급]이라고 하자. 이 제안서([핵심 요약])를 들고
깐깐한 C-Level에게 보고하러 갈 때, 임원이 던질 가장 치명적인 반대 질문 3가지와,
그를 설득하기 위해 제안서 전면에 배치해야 할 명분·근거 논리를 정리해줘.
```

### P3 · 진짜 문제 재정의
```
고객사는 표면적으로 [RFP 요구]를 요청했다. 이 산업군과 고객사의 비즈니스 구조를
고려할 때, 그들이 말하지 못하거나 스스로 깨닫지 못한 진짜 비즈니스 통증은 무엇일까?
선제적으로 짚어주며 역제안할 프레임워크를 도출해줘.
```

---

## 쓰지 말 것

- 근거 없는 문제 재정의 — 오만으로 읽힌다
- 손실 프레임의 공포 마케팅화 — "안 하면 망합니다"는 역효과. 사실과 숫자로만
- 담당자 심리를 제안서 본문에 노출 — 이 문서는 **우리 내부 사고 도구**다
