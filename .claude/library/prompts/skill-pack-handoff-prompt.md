# 제안 고도화 스킬 팩 이식 요청 프롬프트

`proposal-skills-pack.zip`을 대화창에 첨부하고 아래를 그대로 붙여넣는다.

---

## A. 기본형 — 그냥 설치만

```
첨부한 proposal-skills-pack.zip을 이 저장소에 설치해줘.

1. 압축을 풀고 skills/ 안의 8개 폴더를 .claude/skills/ 로 복사
2. library/ 안의 2개 파일을 .claude/library/ 로 복사
3. 이 저장소의 CLAUDE.md에 스킬 목록 섹션과 폴더 구조를 추가
   (zip 안 README.md에 붙여넣을 스니펫이 들어 있어)
4. 기존 스킬과 이름이 겹치면 덮어쓰지 말고 겹치는 항목을 먼저 알려줘
5. 설치 끝나면 커밋하고 푸시

설치 후에 스킬 8개 이름과 각각 언제 걸리는지 한 줄씩 정리해줘.
```

## B. 권장형 — 기존 에이전트와 연결까지

```
첨부한 proposal-skills-pack.zip은 제안서의 논리·근거·구조를 만드는 스킬 8종 팩이야.
설치하고, 이 저장소의 기존 에이전트·스킬과 물리게 연결해줘.

[설치]
1. skills/ 8개 폴더 → .claude/skills/ , library/ 2개 파일 → .claude/library/
2. CLAUDE.md에 스킬 목록·폴더 구조 추가 (README.md의 스니펫 참고)
3. 이름 충돌이 있으면 덮어쓰기 전에 먼저 보고

[연결 — 여기가 핵심]
4. 이 저장소에 리서치·조사 담당 에이전트가 있으면,
   - 출처 티어를 매기는 대목에 source-grading을 걸고
   - 진단·시사점 대목에 insight-derivation을 걸어줘
5. 덱·문서 조판 스킬이 있으면, 조판 직전에 pyramid-principle →
   storyline-builder를 거치도록 순서를 명시해줘
6. 연결한 지점을 파일명·줄번호로 정리해서 보고

[검증]
7. 아무 과제나 하나 잡아서 파이프라인을 한 번 돌려봐.
   .claude/library/proposal-pipeline.md의 0~9단계 순서대로.
   각 단계에서 어떤 스킬이 걸렸는지 표로 보여줘.

작업 끝나면 커밋·푸시.
```

## C. 팀에 처음 소개할 때 덧붙일 문단

```
이 팩이 필요한 이유:
지금 스킬들은 "어떻게 보이게 할까"(덱·대시보드 조판)에 쏠려 있고,
"무엇을 왜 그렇게 주장하는가"를 만드는 자산이 없다.
그래서 리서치는 쌓이는데 인사이트가 안 나오고, 제안이 조사와 따로 논다.
이 8종이 그 사이를 메운다.

설치 후 지시 방법이 바뀐다.
"시장조사 해줘" → 팩트 수집에서 멈춘다.
"이 브랜드가 20대에게 안 먹히는 이유가 인지도인지 이해도인지 판정해줘.
 관점 한 문장부터 잡고, 핵심 수치는 교차 확인해서 등급 달고,
 인사이트는 사용자 여정 어디서 막히는지까지 내려가서 제안이랑 연결해줘.
 마지막에 결론부터 목차 짜고 덱으로."
→ 이러면 0~8단계가 전부 걸린다.
자세한 건 .claude/library/proposal-pipeline.md 참조.
```

## 설치 후 첫 실전 지시 예시

```
{클라이언트}의 {서비스} 리뉴얼 제안이야. 파이프라인 태워줘.

- 결정 질문: {무엇을 판정해야 하는가}
- 조사 관점은 4개로 먼저 선언하고 시작해
- 현행 서비스는 ux-audit 8지표로 진단하고, 문제는 화면 캡처에 번호 찍어서 고정해
- 핵심 수치는 독립 출처 2건 교차 확인, 못 찾으면 DATA GAP
- 인사이트는 Issue → Approach 표까지 만들어
- 결론부터 목차 짜고 덱으로 조판
```
