# 프로젝트 노트 관리 규칙

## 파일 생성
- 신규 프로젝트 시작 시 `.claude/projects/` 폴더 아래에 프로젝트별 노트 파일을 생성한다.
- 파일명 형식: `YYYYMM_프로젝트명.md`
- 신규 파일은 `.claude/library/prompts/project-note-template.md` 구조를 그대로 복사해서 시작한다.

### 반자동 생성 절차 (트리거 → 즉시 실행)
- **트리거**: 사용자가 클라이언트/건을 특정해 착수 신호를 줄 때("○○ 프로젝트 시작/노트 만들어/진행하자"). **새 대화(세션) 시작만으로는 생성하지 않는다** — 폴더 이름에 프로젝트명이 필요하기 때문.
- **실행(4단계, 묻지 말고 한 번에)**:
  1. 이름 확정 `YYYYMM_프로젝트명.md` (산출물 다수면 폴더 `YYYYMM_프로젝트명/` + `00-note.md`)
  2. 템플릿 복사해 생성, 헤더는 아는 만큼 채움
  3. **즉시 `git add`→`commit`→`push`** (임시 컨테이너 — 푸시 전 소실 위험)
  4. 생성 경로 한 줄 보고
- 이후 갱신(세션 종료·결정 확정) 때도 노트 수정 후 **커밋·푸시**까지 완료한다.

## 파일 구성
각 프로젝트 파일은 헤더(클라이언트·업무 범위·일정·견적·상태) + **요약 섹션** + **원본 로그 섹션**으로 구성한다.

- **요약 섹션**: 항상 "최신 결정사항·근거·다음 액션"만 담고, 매 세션 종료 시 덮어써서 갱신한다.
- **원본 로그 섹션**: 세션의 논의·시행착오·버려진 대안을 날짜 헤더로 append만 한다 (절대 덮어쓰거나 삭제하지 않음).

요약만 남기면 결정 근거·뉘앙스가 유실되므로, 디테일은 로그에 보존하고 요약은 결론 위주로 압축한다.

## CHANGELOG.md — 분류·규칙 변경 이력 (선택, 자산성 프로젝트는 필수)

에이전트·스킬·온보딩 자산처럼 **버전이 올라가고 팀이 다시 설치·배포해야 하는 프로젝트**는
`00-note.md` 옆에 `CHANGELOG.md`를 둔다.

```
.claude/projects/YYYYMM_프로젝트명/
├── 00-note.md      ← 요약(덮어쓰기) + 원본 로그(append)
└── CHANGELOG.md    ← 분류·규칙 변경 이력 (최신이 맨 위)
```

**왜 따로 두나** — 원본 로그는 "그날 무슨 얘기를 했나"라 길고 시간순이다.
`CHANGELOG.md`는 "**무엇이 바뀌어서 팀이 뭘 다시 해야 하나**"만 한 줄로 뽑아, 훑으면 바로 잡힌다.
git 커밋 로그와도 다르다 — 커밋은 파일 변경, 이 표는 라우팅·산출 포맷·폴더 분류의 변경을 담는다.

**표 형식 고정**: `날짜 | 버전 | 무엇이 바뀌었나 | 왜 | 영향 파일 | 팀 공지 필요 여부`

**한 줄 추가하는 기준**: 트리거(라우팅) 변경 · 산출 포맷 변경 · 폴더 분류 변경 · 재설치/재배포 필요.
오타·문구 다듬기는 커밋으로 충분하니 추가하지 않는다.

**버전 이름**: `대상 + 판번호` (예: `agent-pack v8`). 날짜만 쓰면 나중에 어느 판인지 못 찾는다.
배포 대상 폴더에는 `VERSION.md`를 같이 두어, 받는 쪽이 자기가 몇 판을 설치했는지 확인할 수 있게 한다.

## 히스토리를 쌓는 4층 구조

노트 하나에 다 담으면 검색이 안 되고, 층을 너무 쪼개면 아무도 안 쓴다. 아래 4층으로 고정한다.

| 층 | 파일 | 담는 것 | 갱신 방식 |
|---|---|---|---|
| 1. 전체 현황 | `.claude/projects/_index.md` | 프로젝트 한 줄씩 — 분류·상태·최근 갱신·노트 링크 | 노트 생성·상태 변경 시 그 줄만 수정 |
| 2. 프로젝트 요약 | `00-note.md` 요약 섹션 | 지금 기준 결정·근거·다음 액션 | 덮어쓰기 |
| 3. 프로젝트 로그 | `00-note.md` 원본 로그 | 그날 논의·버린 대안 | append only |
| 4. 배포 이력 | `CHANGELOG.md` + `VERSION.md` | 팀이 다시 설치·배포해야 하는 변경 | 최신이 맨 위로 append |

### `_index.md` — 프로젝트 인덱스 (필수)

폴더 이름만으로는 지금 어느 단계인지 모른다. `.claude/projects/_index.md`에
`착수 | 프로젝트 | 클라이언트 | 분류 | 상태 | 최근 갱신 | 노트` 한 줄을 유지한다.
**노트를 새로 만들 때와 상태가 바뀔 때, 커밋 전에 이 줄을 같이 고친다.**

### 분류 태그 — 고정 어휘

두 축을 슬래시로 붙인다: `업무유형/영역`.

- **업무유형**: `제안`(수주 전) · `실행`(수주 후) · `사내자산`(에이전트·스킬·온보딩) · `리서치`(단독 조사)
- **영역**: `브랜딩` · `게임UI` · `웹디지털` · `영상모션` · `기타`

예: `실행/웹디지털`, `사내자산/기타`. **자유 태그를 만들지 않는다** — 값이 부족하면
`_index.md`의 어휘표를 먼저 고치고, 그다음 태그를 쓴다.

### 산출물 파일명 — 번호 + 종류 + 날짜

한 프로젝트에서 같은 종류의 산출물이 여러 판 나온다. 날짜가 없으면 어느 게 최신인지 모른다.

```
.claude/projects/202608_클라이언트_업무/
├── 00-note.md
├── CHANGELOG.md                       ← 자산성 프로젝트만
├── 01-리서치대시보드-20260811.html
├── 02-회의록-20260823.md
└── 03-제안덱-20260901.html
```

번호는 만든 순서, 뒤 날짜는 그 판을 만든 날. **기존 판을 덮어쓰지 않고 번호를 올린다** —
"그때 왜 그 결론이었지"를 되짚으려면 이전 판이 남아 있어야 한다.

### 배포판에는 git tag를 같이 단다 (권장)

`CHANGELOG.md`는 무엇이 바뀌었는지를, git tag는 **그 시점의 파일 전체**를 잡아 둔다.
자산 판번호가 올라갈 때 `git tag agent-pack-v8.1 && git push origin agent-pack-v8.1`.
팀원이 "내가 받은 게 몇 판인지" 확인하고 그 판을 통째로 다시 받을 수 있다.
