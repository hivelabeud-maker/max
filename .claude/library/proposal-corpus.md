# 제안서 코퍼스 — 실제 수주 산출물에서 뽑은 골격

> 하이브랩이 실제로 만든 제안서·발표 원고를 해체해서 재사용 가능한 규칙으로 만든 문서.
> **여기 적힌 것은 전부 실물에서 나왔다.** 일반론이나 교과서 구조를 섞지 않는다.
> 에이전트가 제안서·원고를 만들 때 이 파일을 기준으로 삼는다.

- 최초 작성: 2026-09-07
- 원본 자산: 코웨이 BEREX GUI 제안서(Figma 68슬라이드) · 동 제안 발표 대본(21분 21초, 김효정)
  · 제안서 조립용 템플릿(KT·42dot·Clay 추출) · 제안사례 자산 활용 계획(17건 인덱스)

## 1. 제안서 골격은 세 종류다

세 자산의 목차가 서로 다르다. 발주 성격이 달라서다. **먼저 어느 형인지 판정하고 시작한다.**

| | **A형 · 컨셉 제안** | **B형 · 수행 제안** | **C형 · UX 전략·Discovery** |
|---|---|---|---|
| 원본 | 코웨이 BEREX GUI (68p) | KT 인텔리전스 · 42dot Renewal | 42dot Recruit Research (42p) |
| 언제 | BX·GUI·디자인 컨셉을 파는 발주 | 구축·운영까지 포함한 SI성 RFP | 전략·Discovery 단독 발주, 또는 시안 전 단계 |
| 판정 신호 | "컨셉", "방향성", "시안" | "수행범위", "일정", "운영", "품질관리" | "UX 전략", "리서치", "진단", "개선 방향" |
| 장 수 | 7장 | 10장 | 8단 |
| 무게중심 | 05~07장(트렌드·전략·컨셉)이 절반 이상 | 06~09장(범위·방법론·일정·운영) | 축별 레퍼런스가 전체의 절반 |
| 승부처 | 컨셉 3안의 완성도 | 수행 신뢰도와 리스크 대응 | 3축 전략의 변별력과 레퍼런스의 밀도 |

RFP가 A와 B를 둘 다 요구하면 A형 7장을 본체로 놓고 B형의 6·7·8·9장을 뒤에 붙인다.
**부분 개편·리뉴얼 건은 C형이 기본이다** — 전면 구축이 아니므로 컨셉 3안보다 진단과 개선 축이 먼저다.

## 2. A형 골격 — 코웨이 BEREX 실측

68슬라이드 / 7장 / 발표 21분 21초. **슬라이드당 평균 18.8초.**

| 장 | 제목 | 국문 | 슬라이드 | 발표 | 이 장이 하는 일 |
|---|---|---|---|---|---|
| 01 | Overview | 개요 | 01~05 | 0:00~2:12 | 왜 이 고민을 시작했는지. 질문을 바꾸고 목표를 선언 |
| 02 | Market & User Insight | 시장 리서치 | 06~12 | 2:12~4:23 | 시장 규모·타깃·페르소나 → 니즈 3개로 수렴 |
| 03 | Problem Definition | 문제 정의 | 13~20 | 4:23~6:39 | 문제 3개를 데이터로 입증 → 한 문장으로 재정의 |
| 04 | Opportunity Landscape | 시장 내 기회 요인 | 21~26 | 6:39~8:33 | 경쟁 언어 분석 → 우리만 쓸 수 있는 단어 확보 |
| 05 | Visual Trend | 산업군 UI 트렌드 | 27~32 | 8:33~11:18 | 동종 한계 → 이종업계 → 비주얼 트렌드 → 종합 원칙 |
| 06 | Strategy | 디자인 전략 | 33~38 | 11:18~13:17 | 전략 선언 + 실행 전략 4개 |
| 07 | Concept Proposal | 컨셉 제안 | 39~68 | 13:17~20:53 | 컨셉 3안 + 모션 전략 |

**07장이 30슬라이드로 전체의 44%다.** 컨셉 제안형은 시안에서 승부가 난다. 앞 6개 장은 시안의 근거를 쌓는 과정이고, 분량 배분이 그걸 반영해야 한다.

### 각 장의 내부 구성

**01 Overview** — 표지 → 목차 → 개요 → 질문 전환 → 목표 선언
질문 전환(04p)이 핵심이다. 클라이언트가 이미 아는 사실을 던진 뒤 그 사실의 빈틈을 묻는다.
> "코웨이는 37년간 고객의 집 안에 있었습니다. 그렇다면, 왜 고객의 몸은 아직도 우리에게 낯설게 느껴질까요?"
> "우리가 파는 것은 안마 기계가 아니라, 37년이 쌓아온 신뢰와 안도감 아닐까요?"

**02 Market & User Insight** — 시장 규모(숫자+출처) → 타깃 정의 → 페르소나 3인 → 니즈 수렴
페르소나는 **직업·나이·하루 일과**까지 구체적으로 쓴다. 54세 임원 / 51세 스튜디오 대표 / 57세 내과 전문의.
셋의 니즈를 **공통점 3개로 수렴**하고 끝낸다 — 결정하지 않아도 되는 시간 / 예약 없이 시작되는 루틴 / 관리되고 있다는 확신.

**03 Problem Definition** — 문제 3개 각각 [현상 → 데이터 → 그래서 어떻게 바꿔야 하나] → 종합 재정의
문제마다 숫자가 붙는다. "100개 이상의 버튼, 8단계 메뉴" / "보유자의 70% 이상이 전신 버튼만" / "6개월 만에 18%로 급락".
마지막에 문제를 한 문장으로 다시 쓴다 — "기능 부족이 아니라 시작하기 어려운 구조".

**04 Opportunity Landscape** — 경쟁 언어 분석 → 우리만의 단어 → 진짜 문제 확정
TF-IDF로 경쟁사 4곳과 자사의 메시지를 비교해 **우리만 점유한 단어**를 찾는다.
결론 형태: "코웨이는 '관리'를 말할 수 있는 유일한 브랜드입니다."

**05 Visual Trend** — 동종 한계 → 이종업계 3단 → 비주얼 트렌드 3종 → 종합 원칙
이종업계를 **3단으로 올린다**: 퍼스트클래스 항공(에어프랑스·루프트한자) → 스마트 디바이스(구글 네스트 허브) → 금융 단말(토스 터미널·One UI).
비주얼 트렌드도 3종으로 못 박는다: Liquid Glass / Bento + Round / Luxury Dark UI.

**06 Strategy** — 전략 선언 → 실행 전략 4개
선언(33p)이 먼저다. "어떤 기능을 넣을까가 아니라, 37년 관리 경험을 이 화면에서 어떻게 느끼게 할 것인가."
그 다음 전략마다 **수치 기준**을 준다 — 터치 타겟 66mm 이상, 글씨 18pt 이상.

**07 Concept Proposal** — 컨셉 3안 × [정의 → 프로토타입 영상 → 그리드 → 화면별 포인트] + 모션 전략
안 이름은 A Type / B Type / Alt. 각 안마다 그리드를 다르게 하고 **왜 다른지 설명한다** — 12컬럼은 유연성, 10컬럼은 여백과 집중.
화면은 3종 고정: 대기 화면 / 홈 화면 / 동작 화면.

| 4 | **양측 대립 → 교집합** | p13~17 | 이해관계자 두 편의 목적을 대비시키고 교집합을 한 단어로 |

### 3축 전략 — 실제 형태

축은 세 개고, 각각 **[지원자가 ~할 수 있도록 + 축 이름]** 형식이다.

| 축 | 한 줄 정의 | 실행 방법 |
|---|---|---|
| **exploration** | 지원자가 탐색을 편리하게 할 수 있도록 | 검색·필터·태깅 기능 |
| **Personalization** | 지원자와 딱 맞는 정보에 빠르게 접근할 수 있도록 | 위치·활동 기록·데이터로 맞춤 정보 |
| **Communication** | 지원자와 기업이 소통을 통해 가치관을 공유할 수 있도록 | 직원 인터뷰·기업문화·챗봇 |

**축 이름은 영문 한 단어**, 정의는 국문 한 줄. 이 형식이 반복된다.

### UX INSIGHT Reference — 카드 페이지 구조

이 골격의 본체다. **축 하나당 여러 장을 쓰고, 한 장에 하위 요소 3개가 카드로 들어간다.**

```
[축 이름]  exploration
[축 정의]  지원자가 탐색을 편리하게 할 수 있도록
─────────────────────────────────────────────
┌──────────┐ ┌──────────┐ ┌──────────┐
│ Search   │ │ Filter   │ │ Tagging  │  ← 하위 요소 영문명
│ 키워드    │ │ 원하는    │ │ 관심     │  ← 국문 한 줄 정의
│ 검색으로  │ │ 조건으로  │ │ 키워드로 │
│ 직관적    │ │ 명확하게  │ │ 자유롭게 │
│ [스크린샷] │ │ [스크린샷] │ │ [스크린샷] │
│ LINK     │ │ LINK     │ │ LINK     │  ← 출처 링크 필수
└──────────┘ └──────────┘ └──────────┘
```

**실측 배분** — exploration 3장, Personalization 6장, Communication 3장 = 12장.
축별로 사례를 여러 장에 걸쳐 쌓는다. 한 장에 다 넣지 않는다.

**하위 요소는 축마다 3개로 고정**된다.
- exploration → Search / Filter / Tagging
- Personalization → Job introduction / Locations / Information
- Communication → Chatbot / Interview / Values

**모든 카드에 LINK가 붙는다.** 링크 없는 카드는 이 골격에 존재하지 않는다.

### 양측 대립 → 교집합 한 단어

재정의를 만드는 검증된 방법이다. 한 문장으로 압축하기 전에 **양쪽을 따로 세운다.**

```
Candidate                        Employer
내 커리어에 적합한 기업을 찾는 것    기업의 가치관에 적합한 인재를 찾는 것
              ↘            ↙
                  FIT
                   ↓
구직자와 고용주가 채용 과정에서 시행착오를 줄이고
서로에게 Fit한 관계로 이어질 수 있도록
정보를 효과적으로 공유할 수 있는 사용자 경험을 제공하는 것
```

한 페이지에 한 쪽씩 놓고, 다음 페이지에서 교집합 단어 하나만 크게 띄운 뒤, 그 다음에 문장으로 푼다.
**단어가 먼저고 문장이 나중이다.**

### Audit — 자사 진단 3문제

문제마다 두 칸이다. 원인 분석을 길게 쓰지 않는다.

| | 현상 | 필요 |
|---|---|---|
| Problem 1 | 텍스트 위주의 정보 제공, 시각적 요소 부족 | 기업·구성원 이미지를 활용한 시각적 정보 제공 |
| Problem 2 | 원하는 내용의 정보 탐색이 어려움 | 검색 필터·사용자 데이터로 알맞은 정보 제공 |
| Problem 3 | 직무 중심 구조로 기업 가치관 파악이 어려움 | 기업 문화 콘텐츠 추가로 가치관 전달 |

**Audit의 3문제가 3축 전략과 1:1로 대응한다.** Problem 2 → exploration, Problem 1·3 → Communication.
진단과 전략이 따로 놀면 이 골격은 실패한 것이다.

"Naver Cloud Platform / Architecture & Function Icon", "Osstem Implant / OneClick Function Icon".

> 이 페이지의 목적 문장이 명시돼 있다 — "기능 표현에 대해 그래픽 일관성을 유지하여 베리에이션 한 사례를 모았습니다."

## 4. 숫자 사용법

이 제안서에 나오는 숫자는 전부 셋 중 하나다. 장식용 숫자가 없다.

| 종류 | 예 | 쓰임 |
|---|---|---|

## 5. 발표 원고 규칙 — 21분 대본에서 추출

문서 문장과 말하는 문장은 구조가 다르다. 아래는 실제 대본에서만 나온 규칙이다.

### 오프닝은 개인 경험으로 연다

회사 소개나 감사 인사로 시작하지 않는다. **발표자가 이 문제를 몸으로 아는 이유**를 먼저 말한다.

> "저는 두 아이와 함께 키즈 카페를 가는 일이 많은데, 가끔 구석에 놓여진 안마기를 볼 때 굉장히 반가울 수가 없습니다. 반가운 이유는 하나죠. 딱 그 순간만큼은 제가 휴식을 취할 수 있는 순간이기 때문인데요."

이 문단이 하는 일: 발표자가 타깃과 같은 처지라는 걸 증명한다. 뒤에 나오는 페르소나 3인이 책상에서 만든 게 아니라는 근거가 된다.

**길이 30~50초.** 그 다음 바로 목차를 예고하고 본론으로 들어간다.

### 장 사이에 브릿지 문장을 넣는다

슬라이드를 그냥 넘기지 않는다. 다음 장이 왜 필요한지 한 문장으로 잇는다. 대본에서 확인된 형태:

| 위치 | 브릿지 |
|---|---|
| 개요 → 시장 | "그렇다면 이 목표를 달성하기 위해 우리의 타깃은 누구고 시장은 지금 어떤 모습인지 함께 들여다보겠습니다" |
| 시장 → 페르소나 | "그럼 우리는 질문을 던졌습니다. 사용자가 안마 베드에 누워서 진짜로 원하는 게 무엇인지" |
| 니즈 → 문제 | "그렇다면 확인한 기대가 실제 안마 의자 앞에서는 왜 무너지고 마는 것인지" |
| 문제 → 기회 | "이러한 분석을 바탕으로 우리가 집중해야 될 실질적인 기회 요인들을 살펴보겠습니다" |
| 기회 → 트렌드 | "그렇다면 이 역할을 수행하기 위해 먼저 산업군 전반의 비주얼 트렌드를 살펴보겠습니다" |
| 트렌드 → 전략 | "그렇다면 어떻게 비렉스 화면 위에 구현할지 그 전략을 구체적으로 보여드리겠습니다" |
| 전략 → 컨셉 | "이제 실제 화면에서 어떻게 보여질지 세 가지 타입의 최종 컨셉을 소개해 드리겠습니다" |

패턴은 두 가지다. **질문으로 넘기거나**("왜 무너지고 마는 것인지"), **예고로 넘긴다**("~을 살펴보겠습니다").

### 자문자답으로 전환한다

주장을 바꿀 때 질문을 먼저 던지고 스스로 답한다.
> "이 프리미엄 브랜드를 소비할 우리의 핵심 타깃은 그러면 누구일까요? 핵심 타깃은 50대 이상의 디지털 네이티브 시니어입니다."
> "이러한 초기 진입의 불편함이 반복되면 어떻게 될까요? 구매 직후 높았던 사용 빈도는 불과 6개월 만에 18%로 급락합니다."

### 숫자는 말할 때 한 번 더 강조한다

문서에 있는 숫자를 읽고 지나가지 않는다. "무려", "놀랍게도", "불과"를 붙여 크기를 체감시킨다.
> "**무려** 37년이라는 시간 동안" / "**놀랍게도 무려** 70% 이상의 사용자가" / "**불과** 6개월 만에 18%로"

### 클로징은 짧게

> "이상으로 코웨이 비렉스 안마 베드 GUI 디자인 제안 발표를 마치도록 하겠습니다. 경청해 주셔서 감사합니다."

요약을 다시 하지 않는다. 두 문장으로 끝낸다.

### 분량 환산

| 항목 | 실측 |
|---|---|
| 전체 | 68슬라이드 21분 21초 |
| 슬라이드당 | 평균 18.8초 |
| 선언 슬라이드 | 20~30초 (천천히 읽는다) |
| 데이터 슬라이드 | 25~40초 (숫자를 짚어야 함) |

| 클로징 | 10초 |

**15분 발표는 48슬라이드, 30분은 96슬라이드가 상한이다.**

## 6. 용어 각주 규칙

전문 용어를 슬라이드에 쓸 때 **하단에 별표 각주**를 단다. 실제 사례(35p):

> \*소닉 로고: 브랜드의 정체성을 3~5초 내외의 짧은 소리로 시각화하여, 사용자의 청각 피질을 활성화하고 즉각적인 브랜드 각인과 정서적 몰입을 유도하는 사운드 인터랙션 기법.

> "넷플릭스의 두둠 하는 소리, 헤드스페이스의 부드러운 화음처럼"

## 9. 이 파일을 늘리는 법

새 제안이 끝날 때마다 **이겼든 졌든** 한 번씩 해체해서 여기에 반영한다.

**추가하는 것** — 새로 확인된 골격, 실제로 쓴 문장, 숫자 사용 패턴, 브릿지 문장.
**추가하지 않는 것** — 일반론, 다른 회사 방법론의 요약, 출처 없는 원칙.

졌을 때가 더 중요하다. **어느 장에서 밀렸는지**를 적는다. 그게 게이트 기준이 된다.

| 날짜 | 건 | 결과 | 배운 것 | 반영 위치 |
|---|---|---|---|---|
| 2026-04 | 코웨이 BEREX GUI | 수주 | A형 7장 골격, 선언 슬라이드 4장 배치, 이종업계 3단 상승 | 2·3·5장 |
| 2025-09 | 42dot Recruit Research | 수주 | C형 8단 골격, UX INSIGHT 카드 페이지, 양측 대립→교집합 한 단어, Audit 3문제↔3축 1:1 대응 | 1·2-B·7장 |
