- 작성일: 2026-09-07
- 대상: `marketer` 에이전트 + 연동 스킬
- 목표: "마케터 돌려" 한 마디로 RFP부터 제안서 초안·발표 원고까지, 사람 개입 없이

## 1. 지금 상태 — 세 덩어리가 따로 있다

| 덩어리 | 무엇 | 상태 |
|---|---|---|
| **marketer v9** | 7챕터 체인 + 게이트 G1~G5 | 오늘 반영·푸시 완료. 실전 미검증 |
| **proposal-corpus** | 실제 수주 제안서·발표 대본 해체 골격 | 오늘 신설. 코웨이 1건만 반영 |
| **ax-proposal-orchestrator** | A0~A7 8단계 + 기계 판정 게이트 G1~G7 | 다른 세션 초안(v0.1). 임계값 미검증 |

**두 체계가 같은 일을 다르게 정의하고 있다.** 이걸 먼저 정리하지 않으면 어느 걸 부를지 매번 헷갈린다.

## 2. 목표 상태 — "마케터 돌려"의 최종 형태

RFP를 붙이고 한 마디 하면 아래가 순서대로 돌고, 끝에 네 개가 나온다.

```
RFP 인입
  ↓ 케이스 유형 판정 (신생 / 자산확장 / 리뉴얼 / 정의)
CH1 리서치 — 3트랙 병렬, 각 30건 이상, 전부 카드 + 출처 링크
  ↓ 출처 게이트 (URL 실재 확인 · 티어 분류)
CH2 진단 — TF-IDF 언어 분석 → 포지셔닝 맵 → 빈자리
  ↓ 반례 테스트
CH3 문제 정의 — SCQA → MECE 니즈 3분류 → Belief 한 문장
  ↓ 반례 테스트
CH3.5 재정의 — Before / After / Bridge / Evidence
  ↓ 명분 게이트 (Bridge 단어가 공식 자료 원문에 실재하는가)
CH4 발산 → CH5 전략 확정 → CH6 제안서 구성 → CH7 발표 원고
```

**산출물 4종**
1. 제안서 초안 — 골격 + 페이지 설계, 디자인 자리는 비움
2. 발표 원고 — 경영진용 / 실무진용 2버전
3. 근거 추적표 — 모든 주장 → 출처 ID → 티어
4. **플래그 리포트 — 사람이 볼 유일한 문서**

## 3. 결정 세 가지

### 결정 1 · 두 체계를 marketer로 합친다

`ax-proposal-orchestrator`를 별도 에이전트로 만들지 않고, **그 설계를 marketer 안으로 흡수**한다.

**이유**
- marketer는 팀에 이미 배포됐고(agent-pack v8→v9) 트리거가 손에 익었다. 새 이름을 하나 더 만들면 둘 다 안 쓰게 된다.
- 두 체계의 단계가 실질적으로 같다. A0=케이스 판정, A1=CH1, A2=CH3, A3=신규, A4=CH4, A5=CH6, A6=CH7, A7=신규.
- 흡수하면 marketer 하나만 관리하면 된다.

**흡수하는 것** — 기계 판정 게이트, 플래그 방식, 케이스 유형 판정(A0), 재정의 층(A3), 감사 층(A7).
**흡수하지 않는 것** — A0~A7 단계 이름. CH 번호를 유지한다. 팀이 이미 CH로 말하고 있다.

> 되돌릴 수 있는 결정이다. 실전 검증 후 별도 에이전트가 낫다고 판단되면 분리한다.

### 결정 2 · 게이트를 판단에서 반례로 바꾼다

지금 v9의 게이트는 전부 자기 채점이다. "조사가 충분한가", "축의 근거가 있는가" — 모델이 자기 산출물을 스스로 통과시킨다. **무인 운영에서 이 게이트는 없는 것과 같다.**

초안이 제시한 방식이 정답이다. 판정을 **반례 생성**으로 바꾼다.

| 지금 (판단) | 바꿀 것 (반례) |
|---|---|
| "이 3분류가 MECE인가?" | "분류 1이면서 동시에 분류 2인 사례를 3개 만들어봐" → 만들어지면 겹침 |
| "빠뜨린 게 없나?" | "세 분류 어디에도 안 들어가는 사례를 3개 만들어봐" → 만들어지면 누락 |
| "A안과 B안이 다른가?" | 고유명사를 지우고 서로 바꿔 넣어봐 → 말이 되면 같은 안 |
| "출처가 믿을 만한가?" | URL을 실제로 열어봐 → 안 열리면 삭제 |
| "재정의에 명분이 있나?" | Bridge 단어가 공식 자료 원문에 있는지 문자열 대조 → 없으면 지어낸 말 |

반례가 만들어지면 실패다. 만들어지지 않아야 통과다.

### 결정 3 · 실패해도 멈추지 않는다

지금 v9는 "게이트에 걸리면 지정 챕터로 되돌아간다"고 쓰여 있다. **무인 운영에서 이건 무한 루프다.**

바꿀 규칙:
1. 게이트 실패 → 재시도 **최대 3회**
2. 3회 후에도 실패 → **플래그를 달고 다음 챕터로 넘어간다**
3. 플래그 붙은 항목은 본문에서 빼고 Appendix로 격리
4. 모든 플래그를 마지막에 **플래그 리포트**로 모은다

사람은 플래그 리포트만 본다. 이게 "개입하지 않는다"의 실제 형태다.

## 5. 실행 계획 — 5단계

### Phase 1 · 게이트 엔진 (먼저 해야 하는 이유가 있다)

**왜 먼저인가.** 게이트 없이 리서치를 30개로 늘리면 **쓰레기가 30개씩 쌓인다.** 수량 목표는 품질을 밀어낸다. 30개를 채우려고 T4 출처를 긁어오는 순간 리서치 전체가 무의미해진다. 거르는 장치가 먼저 있어야 한다.

**만들 것** — `.claude/library/gate-engine.md` (신규)

| 게이트 | 위치 | 판정 방식 | 실패 태그 |
|---|---|---|---|
| **G1 진짜 요청** | CH0 | RFP 원문과 문자 중복률 측정 | `[표면 요청 복사]` |
| **G2 출처** | CH1 | URL 실재 확인 + T1~T4 분류. T4 본문 금지 | `[UNVERIFIED]` → Appendix |
| **G3 논리** | CH3 | SCQA의 Q가 1개인가 + MECE 겹침·누락 반례 | `[논리 미검증]` |
| **G4 명분** | CH3.5 | Bridge 단어가 공식 자료 원문에 문자열로 실재하는가 | `[재정의 근거 없음]` |
| **G5 변별력** | CH4 | 3전략 겹침 반례 + 커버리지 + A/B 치환 테스트 | `[변별력 미달]` |
| **G6 추적성** | CH6 | 모든 주장 슬라이드가 출처 ID를 참조하는가 | `[근거없음]` |
| **G7 톤** | CH7 | 금지 표현 대조 + anti-ai-writing 적용 | `[톤 미검수]` |

**G4가 이 파이프라인의 핵심이다.** 리서치와 제안이 연결되는 유일한 지점이고, 명분이 기계적으로 증명되는 곳도 여기뿐이다.

**공통 규칙** — 재시도 3회 → 플래그 → 진행. 게이트 결과는 `--- G4 실패 3회. [재정의 근거 없음] 플래그. Bridge 후보 3개 병기 후 진행 ---` 형식으로 한 줄 출력.

### Phase 2 · CH1 리서치 확장

**3트랙 병렬, 각 30건 이상.**

| 트랙 | 무엇을 | 최소 | 출처 티어 |
|---|---|---|---|
| **R1 동종** | 같은 카테고리 브랜드·제품·서비스 | 30건 | T1·T2 |
| **R2 시장·데이터** | 시장 규모·성장률·소비 데이터·공식 발표 | 30건 | **T1만** |
| **R3 이종** | 같은 문제를 푼 다른 산업 사례 | 30건 | T1·T2 |
| **R4 사용자 발화** | 리뷰·커뮤니티 원문. 별점 낮은 것 우선 | 30건 | T3 허용, 수치화 금지 |

**수집 시점에 섹션 태그를 붙인다.** `→S02` `→S03` 식으로. 나중에 매핑하면 느리다.

**카드 규격** — 리서치 1건 = 카드 1장.

```
┌─────────────────────────────────┐
│ [T1]  동종 · 프리미엄            │  ← 티어 배지 + 분류 태그
│ 브랜드명 / 사례명                │
│ 한 줄 요약 (25자 이내)           │
│ 핵심 수치 또는 인용 1개           │
│ 🔗 출처 링크 (실재 확인됨)        │
└─────────────────────────────────┘
```

**수량이 품질을 밀어낼 위험** — 30건을 채우려고 억지로 긁어오는 것을 막으려면, 못 채웠을 때 **`[DATA GAP: R3 이종 18/30]`** 플래그를 달고 넘어가게 한다. 빈칸이 가짜 30건보다 낫다.

---

### Phase 3 · CH2 진단 강화 + CH3.5 재정의 신설

**TF-IDF 언어 분석** (코웨이에서 검증된 방식)
1. 경쟁사 4~6곳의 공식 메시지·슬로건·제품 설명을 수집
2. 자사 것도 같이 수집
3. 단어 빈도를 비교해 **경쟁사 전부가 쓰는 흔한 단어**와 **우리만 쓰는 단어**를 분리
4. 결론은 한 문장 — "코웨이는 '관리'를 말할 수 있는 유일한 브랜드입니다"

**포지셔닝 맵 축 도출 4단계**
1. R4 사용자 발화에서 반복되는 대립쌍을 뽑는다 (브랜드 홍보 문구에서 뽑지 않는다)
2. 후보 축 4~6개를 만든다
3. 경쟁사를 배치해봤을 때 **한쪽에 몰리지 않는** 축 2개를 고른다
4. 빈자리마다 "수요가 있는 빈자리인가, 아무도 안 가는 이유가 있는 빈자리인가"를 판정

**CH3.5 재정의 층** (신규)

| 칸 | 내용 | 규칙 |
|---|---|---|
| Before | 시장이 지금 클라이언트를 어떻게 부르는가 | R1·R2 인용 |
| After | 우리가 제안할 새 정의 | Before와 의미 중복률 임계 이하 |
| **Bridge** | 두 정의를 잇는 **한 단어** | 기능어 금지. 공식 자료 원문에 실재해야 함 |
| Evidence | Bridge가 정당한 이유 | 출처 ID 필수, T1·T2만 |
| Statement | 재정의 한 문장 | |

### Phase 4 · 대시보드 렌더링

`mx-research-dashboard-design` 스킬에 세 가지를 추가한다.

- **카드 그리드 뷰** — 03 경쟁 리서치 / 06 이종업계를 표에서 카드로 교체. 티어 배지 + 출처 링크 필수
- **포지셔닝 맵 뷰** — 04번. 2축 산점도 + 빈자리 하이라이트
- **TF-IDF 뷰** — 08 밸류 키워드에 통합. 흔한 단어 / 우리만의 단어 2열 대비
- **플래그 리포트 뷰** — 신규. 12번째 뒤에 추가

### Phase 5 · 실측 (임계값 캘리브레이션)

초안이 스스로 인정한 대로, 아래 숫자는 아직 근거가 없다.

| 임계값 | 초안값 | 검증 방법 |
|---|---|---|
| RFP 문자 중복률 | 60% | 실제 RFP 3건 |
| Before/After 의미 중복률 | 70% | 과거 제안 3건 역산 |
| 재시도 횟수 | 3회 | 플래그 발생 빈도 관찰 |
| 트랙별 최소 건수 | 30건 | 1건 완주 후 소요 시간 측정 |

**실제 RFP 3건으로 돌려서 플래그 발생 빈도를 봐야 임계값이 잡힌다.** 그 전까지는 전부 잠정값이다.

## 6. 순서와 근거

```
Phase 1 게이트 엔진 ──→ Phase 2 리서치 확장 ──→ Phase 3 진단·재정의
                                                        ↓
                          Phase 5 실측 ←── Phase 4 렌더링
```

- **1이 2보다 먼저** — 거르는 장치 없이 수집량만 늘리면 T4가 쌓인다.
- **3이 2보다 나중** — TF-IDF와 포지셔닝 축은 R1·R4 수집 결과가 있어야 돌아간다.
- **4가 마지막에 가까운 이유** — 렌더링은 내용이 확정된 뒤에 붙이는 게 재작업이 적다.
- **5는 1~4가 다 있어야 시작** — 임계값은 전체를 한 번 완주해야 나온다.

## 7. 알려진 위험

| 위험 | 내용 | 대응 |
|---|---|---|
| **수량이 품질을 민다** | 30건을 채우려고 T4를 긁어옴 | G2를 Phase 1에서 먼저 세움 + DATA GAP 플래그 허용 |
| **한 세션 완주 시간** | 4트랙 × 30건 = 120건 수집에 시간이 오래 걸림 | 1건 완주로 실측 후 건수 조정. 트랙별 상한을 둘 수도 있음 |
| **G4 문자열 대조의 맹점** | 한자어·동의어를 놓친다 | 1차는 문자열, 실패 시 동의어 확장 1회 재시도 |
| **플래그가 너무 많이 뜬다** | 리포트가 100줄이면 사람이 안 본다 | 플래그를 심각도 2단계로 나눔 — 본문 진입 차단 / 참고 |
| **코퍼스가 1건뿐** | 코웨이 하나로 만든 골격이 일반화되지 않을 수 있음 | 진 제안서 2~3건 확보가 최우선 미해결 과제 |

## 8. 자동화하지 않는 것

경계를 미리 그어둔다. 여기까지가 파이프라인이고, 그 밖은 사람이 한다.

- **컨셉 네이밍의 결** — 후보만 생성한다. 최종 선택은 사람.
- **미감 마감** — 픽셀 정렬, 여백, 이미지 선택.
- **디자인 시안** — 자리와 컨셉 정의까지만 만든다.
- **클라이언트 금기 영역** — 정치·이슈·전임 임원. 사전에 목록으로 주입해야 한다.
- **최종 출고 승인**

## 9. 아직 못 채운 것

| 필요한 것 | 왜 | 없으면 |
|---|---|---|
| **진 제안서 2~3건** | 어느 장에서 밀리는지가 G5·G6 기준 | 게이트가 이긴 사례에만 맞춰짐 |
| **견적서 + 실투입 공수** | G5 실행가능성 점수의 근거 | 점수가 감에 의존 |
| **클라이언트 수정 요청 메일** | 어디서 반려되는지 | 게이트가 실제 반려 지점을 못 잡음 |
| **금기 영역 목록** | 클라이언트별 지뢰 | 파이프라인이 밟는다 |
| Drive 제안 사례 폴더 전체 | 코퍼스 확장 | 코웨이 1건 편향 |
