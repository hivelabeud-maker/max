## 요약 (매 세션 종료 시 갱신)

- **핵심 결정사항**
  - 마케터를 **7챕터**로 연장했다. `0 RFP → CH1 조사 → CH2 진단 → CH3 문제정의 → CH4 발산 → CH5 전략 확정 → CH6 제안서 구성 → CH7 발표 원고`.
  - **라우팅을 둘로 나눴다.** "마케터 돌려"는 CH4에서 멈춘다(리서치 목적). 제안서·원고까지는 **"제안서까지 돌려줘" / "마케터 풀로"**.
  - **검증 게이트 5개(G1~G5)를 챕터 사이에 걸었다.** 기존에는 `critic`·`review-panel`·`fact-checker`·`tone-guardian`이 존재만 하고 사람이 따로 불러야 했다. 이제 체인이 자동으로 통과시킨다. 걸리면 지정 챕터로 되돌아가고 그 사실을 먼저 알린다.
  - **CH5~CH7의 기준 문서로 `.claude/library/proposal-corpus.md`를 신설**했다. 실제 수주한 코웨이 BEREX 제안서(Figma 68슬라이드 7장)와 발표 대본(21분 21초)을 해체해 만들었다. 제안서 골격을 새로 지어내는 것을 금지하고 이 파일을 따르게 했다.
  - **제안서 골격이 두 종류라는 것을 확인**했다. A형(컨셉 제안 7장, 코웨이 BEREX)과 B형(수행 제안 10장, KT·42dot 조립 템플릿). RFP 성격으로 먼저 판정한다.
  - **`proposal-script` 스킬을 신설**했다. 제안서를 발표 원고로 바꾸는 스킬이 저장소에 아예 없었다.
  - MECE를 CH2 분류·포지셔닝 축, CH3 문제 분해, CH5 전략 축에 적용하도록 명문화했다.

- **결정 근거**
  - 기존 체인은 CH4(방향 후보 2~3개)에서 끝났다. 목표는 제안서 1건인데 절반에서 멈춰 있었다. 자산을 아무리 넣어도 체인이 끊겨 있으면 제안서까지 가지 않는다.
  - 검증 에이전트를 체인에 안 걸면 "수많은 검증"이 구호로 남는다. 게이트로 걸어야 실제로 돈다.
  - Wolff Olins·MECE를 "그 방법론으로 해줘"라고만 지시하면 공개된 일반론이 나온다. 하이브랩 제안서에서 그 방법론이 **어떤 페이지 구조로 나타나는지**는 실물을 해체해야 나온다. 그래서 코퍼스를 먼저 만들었다.
  - 07장 Concept Proposal이 68슬라이드 중 30장(44%)이었다. 컨셉 제안형은 시안에서 승부가 난다는 뜻이고, 분량 배분 규칙에 반영했다.
  - 슬라이드당 18.8초라는 실측치를 얻었다. 원고 분량을 감이 아니라 숫자로 통제할 수 있게 됐다.
  - "마케터 돌려"를 CH7까지 돌리지 않은 이유: 리서치만 필요한 건에 제안서까지 만들면 낭비다. 트리거를 나눴다.

- **미해결**
  - 진 제안서가 아직 없다. 이긴 것만으로는 게이트 기준을 못 잡는다. 어느 장에서 밀렸는지가 G4 판정 기준이 된다.
  - 견적서·실투입 공수 실적이 없어 G3(`critic` 실행 가능성)의 점수가 감에 의존한다.
  - 클라이언트 수정 요청 메일 원문이 없다.
  - Google Drive 제안 사례 폴더(`1V2oXg2_6E2E5p92zNeojmprLZ-qMgCxu`) 전체를 아직 안 읽었다. 이미지 기반 PDF·PPTX는 텍스트 추출이 안 되는 건이 다수(CCD·FANLIGHT·np_bx·kakao_pp·디뮤지엄·제주맥주·제주항공·11번가).
