# 넷마블 2차 페이크 플레이어블 (NEON DEFENSE)

- **클라이언트**: 넷마블 (프로젝트 옥토퍼스)
- **업무 범위**: 9:16 페이크 플레이어블 광고 소재 1종. 1차와 같은 캐릭터(리타), 다른 무드
- **일정**: 2026-09-09 착수 / 납기 미정
- **견적**: 협의중
- **상태**: 1~7단계 구현 완료. QA 전 항목 통과. 고객사 컨펌 대기

## 요약 (매 세션 종료 시 갱신)

- **핵심 결정사항**
  - 1차 프로젝트에 스킨을 얹지 않고 **별도 프로젝트로 복제**했다 (`neon_defense_playable`)
  - 그래픽은 **레퍼런스 무드(어두운 우주 + 네온)**. 넷마블 던전 아트는 안 쓴다
  - 리타(캐릭터)만 재사용. **몬스터·배경은 그림 파일 없이 코드로 그린다**
  - 이펙트는 레퍼런스만큼 화려하게 — 1차에서 줄였던 값을 되돌렸다
  - HUD 는 레퍼런스처럼 조밀하게. 표시값 3개 → 10개
  - 길이 21.5초 (브리프 "25초 이내" 충족, 엔드카드 +5초 해도 30초 이내)

- **결정 근거**
  - 우주·네온 무드는 절차적 렌더링이 유리해서 **넷마블 아트 대기 없이 착수**된다.
    브리프의 "우선 가장 기본형으로 캐릭터만 적용한 버전"과도 정확히 맞는다
  - 1차 문서가 "조용한 UI"를 네 번 못박고 있어서, 코드 주석과 설계서를 먼저 다시 썼다.
    안 고치면 다음 세션이 문서를 근거로 되돌린다 (이 저장소가 이미 겪은 사고)

- **다음 액션**
  - (실장) 고객사에 2건 확인 — 우상단 톱니가 순수 장식인 점 / 결과 화면 `STAGE CLEAR`
    타이틀이 1차 금·적 에셋이라 네온 톤과 어긋나는 점
  - (실장) 몹 밀도(동시 최대 680) 판단 — 레퍼런스 화면은 훨씬 성기다. 줄이면 페이싱 재검증 필요
  - (다음 세션) 엔드카드 제작 — 2차 요청이나 미착수. 고칠 곳 7군데는 인수인계 문서에 정리돼 있다
  - (다음 세션) 몬스터/배경/스킬선택 변주 버전 — 브리프의 후속 요청

## 원본 로그 (append-only, 절대 덮어쓰지 않음)

### 2026-09-09
- 작업 지시: `docs/00_인수인계.md` 읽고 1단계부터 진행. HUD 기준은 `docs/reference/브리프_넷마블_2차.jpg`
- 인수인계 문서의 0단계(프로젝트 복제)는 이미 끝난 상태로 인계받았다.
  맥에서 온 파일명이 NFD 라 리눅스에서 경로가 안 잡혀 NFC 로 정규화하고 저장소에 편입
- **1단계 우주 톤** — theme.js 팔레트를 시안/마젠타/잉크 3축으로 전면 교체.
  screens.js drawBG 를 별 3층 + 성운 2 + 네온 격자 + 비네트로 재작성.
  계획은 "폴백 격자 색만 시안으로"였는데, 격자만으로는 우주가 아니라 빈 격자무늬라 키웠다.
  별 난수는 게임 RNG 와 분리했다 — 렌더가 시드를 소비하면 재현이 깨져 QA 수치가 매번 달라진다
- **2단계 네온 몹** — 두 번 되돌렸다.
  ① 5종 전부 "어두운 코어 + 밝은 외곽선"으로 만들었더니 동시 680마리에서 화면이 시안 벽이
     되고 주인공이 묻혔다. 속이 빈 도형은 배경 대비가 최대라 채운 도형보다 크고 밝게 읽힌다.
     → 물량 몹은 작고 꽉 찬 보석, 특수 몹만 속이 빈 구조물로 갈랐다
  ② 같은 이유로 hLogic 을 키웠다가 되돌렸다. grunt 는 도트 시절(29)보다 작은 21이다
  (버린 대안: 몹 밀도 자체를 줄이는 것 — 1차의 검증된 페이싱을 흔들게 되므로 보류하고 실장 판단으로 넘겼다)
- **3단계 이펙트** — 부채꼴 3→5발, 볼리 6→12발, 착탄 파열 확률 12→26%, 적중 흩뿌림 신규.
  가장 크게 바뀐 건 발수가 아니라 **가산 블렌딩**이었다. FX.drawWorld 가 일반 블렌딩이라
  우주 배경 위에서 탁한 얼룩으로 보였다 — 탄만 이미 lighter 를 쓰고 있어 재질이 달랐다
- **4단계 피해 집계** — 스킬을 새로 만들지 않았다. 이미 성격이 다른 출처가 넷이라
  (부채꼴/스플래시/볼리/섬멸) 이름과 색만 붙이면 레퍼런스의 "스킬 피해 현황"이 성립한다
- **5단계 HUD** — 하단 요소를 전부 오버레이로 만들어 Stage.pf 를 안 건드렸다.
  덕분에 qa.js 의 play ≥ 430 이 13종 전부 그대로 통과한다.
  실드는 표시만 하지 않고 실제로 동작하게 만들었다 (HP 앞에서 먼저 깎이고 다시 찬다) —
  아무것도 안 하는 게이지는 화면에서 즉시 가짜로 읽힌다
- **6단계 20웨이브** — 카운터만 20칸, 스폰 난이도는 3단계 유지.
  21.5초짜리를 난이도 20단계로 쪼개면 어느 단계도 인상에 안 남는다.
  배너는 제거 — 수명 1.3초라 웨이브당 0.9초에서 상시 겹친다
- **7단계 파이프라인** — release.sh 에 BSD 전용 `sed -i ''` 가 있어 맥에서만 돌던 것을 고쳤다.
  납품 폴더 경로도 환경변수로 뺐다 (프로젝트가 팀 저장소 안에 들어와 그대로 두면 저장소를 더럽힌다)
- 검증은 전부 계측으로 했다. 1차 교훈("같은 지적을 두 번 받으면 추정을 멈추고 실측한다")대로
  몹 밀도·이펙트는 Chromium 실측 캡처, 피해 집계는 헤드리스 하네스 수치로 판단했다
