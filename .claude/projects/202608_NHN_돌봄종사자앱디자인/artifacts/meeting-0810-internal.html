사용자 확정

어르신이 아니라 돌봄 종사자입니다

요양보호사와 생활지원사가 씁니다. 어르신은 이 앱의 사용자가 아니라 돌봄 대상입니다.

파트장 — "돌봄 종사자분들의 연령대가 높아요. 50대 이상 사람들 연령대가 되게 높아가지고, 돌봄 자문단의 의견도 다 쉽게 쓸 수 있는 직관적인, 그리고 크게크게 이런 식의 니즈가 있었거든요."

→ 어르신 대상 서비스의 톤이 아니라 중장년 실무자의 업무 도구 톤. 큰 글자 · 직관적 아이콘 · 굵은 획.

핵심 기능 확정

음성 입력이 사업계획서상 메인입니다

파트장 — "사업 계획서 상에서 음성을 통해서 기록을 하는 게 메인 기능으로 되어 있어가지고 여기에 조금 힘을 주었으면 하고요."

음성 입력 → 실시간 입력 연출 → "입력 종료·변환하기" → AI가 정돈된 문장으로 자동 입력. 요양·생활·전화 전부 공통.

→ 여러 화면 중 하나가 아니라 이 앱의 얼굴입니다. 시안 우선순위 최상위.

AI 표현 확정

AI 느낌은 살리되, 앱이 판정하지는 않습니다

업무 가이드는 어르신 특성(고혈압·땅콩 알레르기 등)을 AI가 분석해 내려주는 것이고, 파트장은 "이 영역 같은 경우에는 뭔가 AI를 활용하는 것에 대한 느낌이라든지 그런 식으로 좀 제공되면 좋을 것 같습니다"라고 했습니다.

→ AI가 도와준다는 인상은 필요하지만 진단·판정한다는 인상은 안 됩니다. 판단은 사회복지사가 합니다. 이 선을 시각적으로 지키는 게 관건입니다.

방향 자유도 양날

정해둔 방향이 없습니다

"따뜻한 톤이냐, 병원 앱처럼 직관적·전문적이냐"는 질문에 내부적으로 정한 것이 없다는 답이었습니다.

김준환 — "자유도가 높다고 생각을 해서 오히려 더 어려울 수도 있을 것 같아요."

→ 우리가 방향을 만들어 갑니다. 대신 초기에 방향을 빨리 확정하는 것이 이 프로젝트의 최대 성공 조건입니다.

예정 · 진행 · 완료 · 중단 · 미수행. 중단은 시작했으나 어르신 컨디션 등으로 못 한 경우, 미수행은 시작조차 못 한 경우입니다. 완료·중단·미수행 모두 사유 입력이 필요합니다.

설계 포인트 — 파트장: "기록이 남겨져 있는지, 아니면 아직 기록을 하지 않은 상태일 경우에는 기록을 입력하게끔 유도할 수 있는 장치 UI가 조금 제공이 되어야 하는 내용입니다." → 카드 하나에 5상태 + 기록 유무가 동시에 읽혀야 합니다. 이 앱에서 정보 밀도가 가장 높은 컴포넌트입니다.

05돌봄 기록 — 3분기선작업 대상
중요 — 기록 화면은 돌봄 종사자 유형(요양보호사/생활지원사) × 업무 유형(방문/전화)에 따라 내용이 다릅니다. 요양보호사는 주로 방문 업무만 하므로 실질적으로 요양 방문 / 생활 / 전화 3분기입니다.

요양보호사 — 방문 · 4단계

1단계 이용자 정보 + 계획 시간 vs 실제 수행 시간 + 체크리스트 → 수행한 체크리스트 선택
2단계 수행 업무 체크박스 — 지난번 수행 내역을 자동으로 불러옵니다. 파트장: "각 어르신별로 수행하는 업무가 비슷비슷하다라고 하더라고요"
3단계 신체 기능 · 식사 기능 · 인지 기능 변화
4단계 특이사항 자유 기록 — 사진 첨부 + 음성 입력

생활지원사 — 3단계

2단계 내용이 요양과 다르고 나머지는 동일. 음성 입력도 동일.

전화

전화로 할 수 있는 업무가 제한적이라 더 간략하게 제공.

음성 입력 — 전 유형 공통

음성 입력 시 입력되는 연출이 이루어지고, 참고할 수 있도록 오늘 수행한 체크리스트 정보를 함께 제공합니다. "입력 종료·변환하기" → AI가 정돈된 메시지로 자동 입력.

실적 시간 처리가 유형별로 다릅니다 — 요양보호사는 기록 입력 시간까지 실적에 포함됩니다. 생활지원사는 오후 2~3시에 별도 기록 시간이 따로 있어서 그때 몰아서 기록합니다. → 생활지원사는 "기록 없이 완료"로 업무를 끝내고 나중에 미기록 건을 모아 보정하는 흐름이 기본입니다. "미기록 목록"이 생활지원사에게는 핵심 화면이 됩니다.
06이상 보고

입력 항목 — 어떤 어르신 / 어떤 내용 / 내가 어떤 조치를 했는지

각 입력 필드에 음성 기록 제공, 사진 첨부 가능.

등록 시 통합 어드민에서 사회복지사가 확인 → 조치 → 그 후속 조치 히스토리를 앱에서 확인할 수 있습니다.

등록하면 오늘 업무에 카드 형태로 등록 시각에 맞춰 노출되고, "기록 보기"로 내용 확인.

07긴급 안부 확인AI 스마트홈 부가 기능

기상청·행안부 데이터로 지역별 기상특보·긴급재난알림을 수집. 예를 들어 성남시에 폭염 경보가 발생하면 성남시 어르신들에게 AI 대화가 발신되어 "괜찮으시죠" 응답을 수집합니다.

돌봄 종사자는 담당 어르신의 응답 여부를 확인합니다. 발생 시각 + 안부 확인 퍼센트. 상세에서 전체 몇 명 중 몇 명 응답, 미응답자 리스트.

생활지원사 전용 구분 — 어르신을 일반 / 중점으로 나눕니다. 중점은 상태가 안 좋은 어르신. 파트장: "안부가 확인되지 않는 사람들 중에서도 중점인 대상자들을 조금 더 주의도 있게 표시를 해야 합니다." → 미응답 × 중점이 겹치는 대상이 가장 강한 시각 위계를 가져야 합니다.

파트장 정리: "AI 대화가 1차로 안부를 확인한 결과를 기반으로 돌봄 종사자가 2차 작업만 하면 되는" 구조.
