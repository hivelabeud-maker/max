# 플레이어블 광고 제작 프로세스

> 선행 4개 프로젝트(Dreamy Match · TOY WAR · Penguin · Pixel Survivor)에서
> **실제로 시간을 잡아먹은 지점**을 막는 순서로 짰습니다.

---

## 0. 왜 이 순서인가 — 실측된 손실 4가지

| 손실 | 이번 프로젝트에서 |
|---|---|
| **에셋이 파일로 전달되지 않음** | 7회 이상 반복. 몬스터·타이틀·배경이 채팅에만 있고 디스크에 없어 반영 불가 |
| **시각 디테일을 1건씩 확인** | 수정 → 스크린샷 → 지적 → 수정 왕복 수십 회 |
| **같은 유형 버그 재발** | 외곽 잔재 3회, 삭제된 좌표 참조 2회, 치환 실패 1회 |
| **빌드 중 장르 전환** | 서바이버 → 게이트 디펜스 → 주인공 포위형. 코드 3회 재작성 |

아래 5단계는 이 4가지를 각각 구조로 차단합니다.

---

## 1. 5단계 (첫 프로젝트 4~5일 / 2회차부터 2~3일)

### P0 — 킥오프 · 반나절
| 산출물 | 내용 |
|---|---|
| **레퍼런스 확정** | 클라이언트가 영상 1~2개를 고른다. 이후 변경 불가 |
| **27초 타임라인 표** | 초 단위 연출 대본. 종이에서 확정 |
| **에셋 발주서** | `02_에셋명세.md` 템플릿에 이번 건 수치를 채워 발송 |

> **게이트: 타임라인 표에 클라이언트 확인을 받고 넘어간다.**
> 장르·페이싱 변경은 이 단계에서만 무료다. P1 이후 변경은 별도 견적.

### P1 — 그레이 빌드 · 1~2일 (아트 없이 시작)
플레이스홀더 도트로 **페이싱·조작·연출을 먼저 완성**한다.
아트를 기다리며 멈추지 않는 것이 핵심.

> **게이트: `node tools/qa.js` 전 항목 통과 + 무입력 완주.**

### P2 — 에셋 수급 · P1과 병렬
클라이언트가 `src/art/raw/` 규격에 맞춰 **파일로** 전달.
받는 즉시 `python3 tools/prep_assets.py` 로 가공 가능 여부만 확인하고 반려/승인.

### P3 — 아트 투입 · 0.5일
```bash
python3 tools/prep_assets.py && python3 tools/build.py && node tools/qa.js
```
데이터 파일(`src/data/*.js`) 수치만 조정. 엔진은 건드리지 않는다.

### P4 — 폴리시 · 1일
**묶음 리뷰**. 한 번에 3~5건씩 모아서 확인하고 일괄 수정.

### P5 — 출고 · 0.5일
네트워크별 빌드 · 규격 검증 · 1080p MP4 추출 · 인수인계 문서.

## 2. 재사용 구조 — 이게 수익 구조다

| 레이어 | 재사용률 | 내용 |
|---|---|---|
| `src/core/` | **100%** | 캔버스·입력·풀·충돌·스프라이트·FX·CTA·디버그 |
| `tools/` | **100%** | 아트 가공 파이프라인 · 빌드 · 헤드리스 QA |
| `docs/` | **100%** | 발주서·인수인계·출고 체크리스트 템플릿 |
| `src/game/` | 60~80% | 장르가 같으면 대부분 재사용 |
| `src/data/` | 0% | 매 프로젝트 새로 (여기가 진짜 작업) |

**2회차부터 P1이 반나절로 줄어듭니다.** 첫 프로젝트가 비싼 이유이자,
두 번째부터 마진이 나오는 이유입니다.

---

## 3. 철칙 5가지 — 어기면 바로 손실로 돌아옴

1. **아트는 폴더로만 받는다.** 채팅·메신저 첨부 금지. `src/art/raw/` 에 파일로.
2. **검토는 묶어서.** 1건씩 확인하면 왕복 비용이 작업 비용을 넘는다.
3. **방향 전환은 P0에서만.** 이후는 견적 변경 사유.
4. **좌표는 실측한다.** 눈대중 비율 금지. 이미지에서 픽셀로 재서 상수화.
5. **그레이 빌드 먼저.** 아트 없이 27초가 완주되어야 P2로 간다.

## 4. 에셋 발주 규격 (클라이언트 전달용 1페이지)

```
src/art/raw/
├─ character.png        주인공 (정면 1컷이면 충분 / 시퀀스면 더 좋음)
├─ bg_room.png          배경 — 반드시 9:16 전체 크기
├─ mob_*.png            몬스터 (실루엣이 다른 3종 이상)
├─ boss_*.png           보스 (잡몹의 4배 이상, 형태가 확연히 다르게)
├─ btn_install.png      설치 버튼
├─ title_win.png        결과 타이틀
└─ stats.png            결과 스탯 패널
```

**4대 규칙**
- 투명 PNG (흰 배경도 자동 제거되나 투명이 항상 깨끗함)
- **그림자·글로우를 굽지 말 것** — 코드가 그린다
- **숫자·텍스트를 굽지 말 것** — 값이 바뀌면 에셋을 다시 받아야 한다
- 배경은 **9:16 전체 크기 단독 발주** — 목업에서 잘라 쓰면 반드시 실패한다

**시퀀스가 있으면**: 프레임 수는 8~12장이면 충분하다.
화면에 30px로 그려지는 몹에 21프레임은 육안 차이 없이 용량만 3배다.
