# 플레이어블 광고 소재 제작 프로세스 (고객사 제안용)

---

## 프로세스 한눈에

```
1. 킥오프          →  2. 아트 방향    →  3. 그레이 빌드   →  4. 아트 투입   →  5. 검수    →  6. 출고
   레퍼런스 확정       원작 or 재해석      아트 없이 완성      실제 비주얼      수정 3R      납품
   ─ 승인 ① ─         ─ 승인 ② ─         ─ 승인 ③ ─        ─ 승인 ④ ─
   0.5일              1~2일               1~2일              0.5일           1일          0.5일
```

**총 5~7일** (아트가 준비된 경우 / 신규 아트 제작 시 별도)

---

## 1단계 — 킥오프 · 0.5일

**고객사 제공**
- 레퍼런스 영상 **1~2편** (플레이 화면 녹화)
- 집행 네트워크 (Meta / Google Ads / AppLovin / ironSource 중)
- 앱 스토어 URL 또는 앱 ID
- 게임 원본 아트 수급 가능 여부

**하이브랩 산출물**
- **연출 기획서** — 25~30초를 초 단위로 쪼갠 타임라인 표
- **에셋 발주서** — 필요한 아트 목록 · 규격 · 우선순위

> ### 승인 게이트 ① — 타임라인 확정
> 장르·조작·연출 순서를 여기서 확정합니다.
> **이후 단계에서의 장르 변경은 재개발에 해당하여 별도 견적입니다.**

---

## 2단계 — 아트 방향 결정 · 1~2일

플레이어블 광고는 **원작을 그대로 재현하지 않습니다.**
30초 안에 이해되고 극적으로 보이는 쪽으로 단순화·과장합니다.

| 방향 | 내용 | 아트 비용 |
|---|---|---|
| **A. 원작 그대로** | 게임의 기존 아트를 가공해 사용 | 낮음 |
| **B. 부분 재해석** | 캐릭터는 원작, 배경·UI는 신규 | 중간 |
| **C. 전면 재해석** | 예: 3D RPG → 8비트 디펜스 | **높음 — 신규 제작** |

> **C안(재해석)이 가장 흔한 요청이자 가장 큰 비용 변수입니다.**
> 원작 아트를 못 쓰므로 캐릭터·몬스터·배경·UI를 새로 만들어야 합니다.
> 이 단계에서 **어디까지 신규 제작인지** 범위를 확정해야 견적이 고정됩니다.

**하이브랩 산출물**: 아트 방향 시안 · 신규 제작 리스트 · 확정 견적

> ### 승인 게이트 ② — 아트 방향 확정
> 이후 아트 컨셉 변경은 추가 견적입니다.

---

## 3단계 — 그레이 빌드 · 1~2일

**아트 없이 먼저 동작하는 시제품을 만듭니다.**
플레이스홀더 도형으로 페이싱·조작감·연출 리듬을 완성합니다.

| 왜 이 순서인가 |
|---|
| 아트를 기다리며 일정이 멈추지 않습니다 |
| 재미 없는 구조에 비싼 아트를 붙이는 사고를 막습니다 |
| 고객사가 **실기기에서 직접 플레이**하고 판단할 수 있습니다 |

**하이브랩 산출물**: 실행 가능한 HTML (모바일 링크로 즉시 확인)

> ### 승인 게이트 ③ — 게임성·페이싱 확정

---

## 4단계 — 아트 투입 & UI 확정 · 0.5일

전달받은 아트를 자동 가공 파이프라인에 넣어 적용합니다.
(배경 제거 · 외곽 정리 · 해상도 최적화 · 인라인 압축 자동)

**하이브랩 산출물**: 실제 비주얼이 적용된 빌드

> ### 승인 게이트 ④ — 비주얼 확정

---

## 5단계 — 검수 · 1일

**수정 3라운드**를 기준으로 합니다.
피드백은 **묶어서 한 번에** 주시면 반영이 빠릅니다.

**자동 검증 항목** (매 빌드마다 실행)
- 기기 10종 레이아웃 (16:9 ~ 21:9 · 태블릿)
- 무입력 방치 시에도 끝까지 완주
- 광고 규격: 외부 요청 0건 · 금지 API 0건 · CTA 자동발동 0건
- 런타임 에러 0건

---

## 6단계 — 출고 · 0.5일

**납품물 5종**

| # | 산출물 | 용도 |
|---|---|---|
| 1 | `playable.html` | **애드네트워크 업로드용 단일 파일** (외부 요청 0) |
| 2 | `playable_video.html` | 영상 추출용 |

| 4 | 소스 일체 | 향후 수정·재활용용 |
| 5 | 인수인계 문서 | 수정 방법 · 교체 지점 · 규격 체크리스트 |

## 고객사가 준비해주셔야 할 것

### 필수
- [ ] 레퍼런스 영상 1~2편
- [ ] 집행 네트워크
- [ ] 스토어 URL 또는 앱 ID
- [ ] **아트 원본 — 반드시 파일로** (폴더 전달 · 메신저 첨부 지양)
- [ ] **티저 영상 또는 이미지** ※ 아래 참고

### 아트 규격 4가지
1. **투명 PNG** (흰 배경도 처리 가능하나 투명이 항상 깨끗함)
2. **그림자·글로우를 굽지 말 것** — 코드가 그립니다
3. **숫자·텍스트를 굽지 말 것** — 값이 바뀌면 아트를 다시 받아야 합니다
4. **배경은 9:16 전체 크기 단독** — 목업에서 잘라 쓰면 반드시 실패합니다

### ※ 반드시 알려드릴 것 — 티저 소재
**플레이어블 HTML만으로는 광고를 만들 수 없습니다.**
Meta·Google 모두 피드에 먼저 노출될 **티저 영상 또는 이미지**가 별도로 필요하고,
이용자가 그걸 탭해야 플레이어블이 전체화면으로 열립니다.
납품물 3번(MP4)을 티저로 활용하실 수 있습니다.

## 견적 구조

| 항목 | 비고 |
|---|---|
| **기본 1편** | 25~30초 · 단일 HTML · 1080p MP4 · 소스 · 인수인계 문서 |
| 신규 아트 제작 | 2단계 C안(재해석) 선택 시. 범위에 따라 산정 |
| 캐릭터 추가 교체 | 1종당 |
| A/B 변주 | 1안당 (인트로 유무 · CTA 위치 · 난이도) |
| 다국어 | 1개 언어당 (문구만 교체) |
| **장르 변경** | **별도 프로젝트** (승인 게이트 ① 이후) |

---

## 계약서에 명시할 3가지

1. **수정 라운드 3회** — 초과 시 별도 산정
2. **승인 게이트 이후 변경은 추가 견적** — 특히 게이트 ①(장르)·②(아트 방향)
3. **아트 전달 기한** — 지연 시 납기 순연

> 이 3가지가 빠지면 "조금만 더" 요청이 무한히 누적됩니다.
> 반대로 명시해두면 게이트 전에 고객사가 충분히 검토하게 되어 결과물 품질도 올라갑니다.
