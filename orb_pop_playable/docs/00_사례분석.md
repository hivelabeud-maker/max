# 선행 3개 사례 분석 — 무엇이 되었고 무엇이 깨졌는가

분석 대상
- `dreamy_match_playable` — 3매치 퍼즐, Meta 규격 검증 완료, 256KB **(성공)**
- `디펜스게임_MD` (TOY WAR) — 스쿼드 러너 디펜스, 프로토타입 48KB **(설계 성공 / 출고 실패)**
- `PENGUIN_ICE_RUSH` — 다층 발판 수집형, 단일 HTML 666KB **(완성도 높음 / 광고로서 실패)**

---

## 1. 한 줄 판정

| 프로젝트 | 플레이 길이 | 조작 | 상태 | 판정 |
|---|---|---|---|---|
| Dreamy Match | 25~35초 | 드래그 1종 | 납품 가능 | **성공** — 그대로 계승할 기준선 |
| TOY WAR | 28.9초 | 좌우 드래그 1종 | 프로토타입에서 정지 | **설계는 정답, 파이프라인에서 죽음** |
| Penguin Ice Rush | **95초** | D-패드 + 점프 (2종) | 납품 가능 | **광고 설계 실패** — 제품은 좋으나 광고가 아님 |

## 2. 실패 원인 6가지 (재발 방지 대상)

### F1. 플레이 길이 95초 — Penguin
튜토리얼 3.2초 + STAGE1 42초 + 전환 1.3초 + STAGE2 48초.
플레이어블 광고의 유효 체류는 **15~30초**다. 95초 설계는 90%의 유저가 엔드카드를 못 본다는 뜻이다.
게다가 "아이템 전량 수집"은 **목표 달성이 지연되는 구조**라 도파민 곡선이 평평하다.
→ **규칙: 총 길이는 타임라인에 초 단위로 고정한다. 시뮬레이션 결과에 맡기지 않는다.**

### F2. 조작 2종 (D-패드 + 점프) — Penguin
한 손 세로 광고에서 4방향 패드 + 점프 버튼은 학습 비용이 크다.
판정 영역 디버그 모드(`?debug=1`)까지 만들어야 했다는 것 자체가 조작이 어렵다는 증거다.
→ **규칙: 조작은 1종. 드래그만. 나머지는 전부 자동.**

### F3. 외부 CDN 의존 — TOY WAR
`ASSET_BASE = 'https://d8j0ntlcm91z4.cloudfront.net/...'` 상태로 정지했다.
Meta/AdMob은 **외부 요청 금지**라 이 상태로는 출고 자체가 불가능하다.
샌드박스에서 CDN 업/다운로드가 막혀 인라인 전환도 못 했다.
→ **규칙: 1일차부터 로컬 파일 + 인라인 빌드 스크립트를 갖춘다. 원격 URL은 코드에 넣지 않는다.**

### F4. 목업에서 배경 크롭 — TOY WAR
GUI 목업에서 UI를 잘라 넣었으나, 게이트·캐릭터가 안 걸린 **깨끗한 방 구간이 세로 198px뿐**이라
960px 화면을 못 채웠고 레인 바깥이 검게 비어 롤백했다.
→ **규칙: 배경은 처음부터 9:16 전체 크기 단독 발주. 목업에서 잘라 쓰지 않는다.**
→ 단, **HUD 칩·버튼·패널 크롭은 품질에 문제가 없었다.** 이 구분은 유효하다.

### F5. MP4 → 스프라이트 자동 굽기 — TOY WAR
영상 배경이 어두운 그라데이션이라 캐릭터 외곽에서 키잉이 깨졌다. 롤백.
→ **규칙: 모션은 (a) 스프라이트 시트 프레임 또는 (b) 단일 스프라이트 코드 변형만 쓴다.
영상 키잉은 단색 크로마키로 재촬영되지 않는 한 시도하지 않는다.**

### F6. 이미지에 숫자·텍스트 베이크
게이지에 "107", 뱃지에 "6명", 무기칩에 "방패병"이 그려져 있어 값이 바뀌면 에셋 재생성이 필요했다.
3-슬라이스 + 코드 렌더로 해결했다.
→ **규칙: 변하는 값은 100% 코드 렌더. 이미지는 프레임만 담당.**

## 3. 성공 패턴 8가지 (전부 계승)

| # | 패턴 | 출처 | 계승 방식 |
|---|---|---|---|
| S1 | **Fail-to-win** — 절대 지지 않음 | Dreamy `movesUsed>=7` 강제 클리어 / Penguin `allowGameOver:false` | 플레이어 HP 하한 클램프. 사망 상태 자체를 없앰 |
| S2 | **무입력 오토플레이** | TOY WAR 3초 무입력 → 자동 진행 | 1.2초 무입력 시 자동 이동 + 손가락 힌트 재출력 |
| S3 | **첫 상호작용은 무조건 성공** | TOY WAR 첫 게이트 양쪽 다 플러스 | 첫 3초 적은 느리고 약함. 첫 킬이 1초 안에 발생 |
| S4 | **폭 고정 / 높이 가변 반응형** | Dreamy `H=clamp(720*vh/vw,980,2100)` / Penguin 540 고정 | W=540 고정, H=clamp(540*vh/vw, 810, 1200). 레터박스 0 |
| S5 | **에셋 폴백 2단계** | TOY WAR 컷아웃 실패 시 코드 드로잉 | 에셋 0장으로도 27초 완주. 아트 대기 없이 페이싱 튜닝 가능 |
| S6 | **스프라이트 알파 자동 측정** | TOY WAR `measure()` — 발밑·총구 자동 산출 | 캐릭터 교체 시 좌표 수작업 제거의 핵심 |
| S7 | **헤드리스 QA 스크립트** | Penguin `qa_check.js` (228줄, 무의존) | **최대 자산.** 기기 10종 레이아웃 + 봇 플레이 + 런타임 에러 0 검증 |
| S8 | **CTA 폴백 체인 + 중복 방지** | Dreamy `fireCTA()` | FbPlayableAd → mraid → ExitApi → window.open, 1회만 |

## 4. 이번 프로젝트에 그대로 옮길 수치 기준선

Dreamy의 검증 결과가 사실상 사내 규격이다.

| 항목 | 기준 | 근거 |
|---|---|---|
| 파일 크기 | **1.5MB 이하** (Meta 2MB의 75%) | Dreamy 256KB / Penguin 666KB 모두 여유 있었음 |
| 외부 요청 | **0건** (런타임 후킹으로 실측) | 문자열 검색이 아니라 fetch/XHR/open 후킹 검증 |
| 이미지 포맷 | **WebP + base64 인라인** | PNG 대비 약 40% 절감, iOS14+/Android4.3+ |
| 문법 | **ES5** | 구형 웹뷰 호환 (Dreamy가 이미 채택) |
| 금지 API | localStorage / eval / XHR / fetch / WebSocket / document.write | Meta 심사 항목 |
| 사운드 | 없음 | 대부분 음소거 재생. 용량만 먹음 |
| 총 길이 | **27초 ±2초** | 25~35초 구간의 하단. 짧을수록 완주율이 높음 |
